# W1.5 A4 异常解读实施计划

## Context

`GET /api/ai/insights/dashboard` 目前是占位实现（`backend/api/routers/ai.py` L194-L200），只校验 `window` 并返回空数组。W1.5 要求把它替换为真实的只读异常解读：汇总既有驾驶舱 KPI 规则告警与 MRP 未处理异常，输出结构化告警（指标/当前值/阈值/偏离程度/关联单据/下钻路径/归因提示/建议），并生成可读解读文本。

约束：不改既有 API 契约已生效部分；只读；不新增写操作；权限只来自本体生成物与意图注册表；金额按角色裁剪；解读文本模板优先，LLM 仅润色且必须通过数字回查，失败/配额耗尽完整降级；不使用 PG 专有语法；前端不新增依赖。

设计依据：`2026-11-24/ai-ontology-design/outputs/02-实施计划-DIERP-AI原生化.md` W1.5（验收：`{alerts:[{code,title,severity,evidence[],suggestion,drilldown}]}`，evidence 含 `table + record_ref`，无证据不输出；模板结构不变；不改 `/api/dashboard/*`）。

## 现有可复用能力（不重算指标）

- 六域 KPI：`backend/services/planning/management_dashboard.py` 的 `ManagementDashboard.overview(db)`。
- 驾驶舱规则求值：`backend/services/dashboard/alerts.py` 的 `build_alerts(db, scope, data)`，已覆盖 `HOME/MANAGEMENT/PRODUCTION/PROGRESS/FINANCE/SALES` 六个 scope，阈值来自 `DashboardRule`（本体生成物），无需重写比较逻辑。
- 资金 KPI / 工序进度：目前是 `backend/api/routers/dashboard.py` 内的 `_finance_kpi`、`_progress_rows`（L54-L137）。抽到服务层供看板路由与解读层共用，逻辑不改。
- MRP 异常：`MrpException` + 意图 `open_mrp_exceptions`（`backend/services/ai/intents/planning_exceptions.py`），角色白名单 `PLANNER/GENERAL_MANAGER/ADMIN`。
- 数字回查：`backend/services/ai/answer.py` 的 `allowed_numbers` / `numbers_subset`。
- LLM：`backend/services/ai/llm.py` 的 `get_llm_client`、`complete`、`last_model`、`LLMError`；配置 `AISettings.ai_llm_*`。

## 后端设计

### 1. 新增 `backend/services/dashboard/kpi.py`

把 `_finance_kpi`、`_progress_rows` 从 `backend/api/routers/dashboard.py` 原样迁出为 `finance_kpi(db)`、`progress_rows(db, window, order)`；路由改为导入，函数体与返回结构不变。这样解读层复用既有取数，不复制财务/进度口径。

### 2. 新增 `backend/services/ai/insights.py`

核心函数：

```python
def build_dashboard_insights(db, window: str, role: str) -> dict
```

步骤：
1. `overview = ManagementDashboard.overview(db)`；`finance = finance_kpi(db)`；按需构造各 scope 的输入数据（与 `dashboard.py` 各驾驶舱路由一致）。
2. 依次对 `MANAGEMENT → PRODUCTION → PROGRESS → FINANCE → SALES → HOME` 调 `build_alerts(db, scope, data)`；按 `metric` 去重（HOME 的 OEE 与 MANAGEMENT 重复时保留 MANAGEMENT）。
3. 为每个规则告警补结构化字段与证据（每个指标固定证据查询，证据上限 5 条并记录 `evidence_total`）：
   - `equipment.oee` → `work_centers`（低于阈值的工作中心）/ `equipment_failures`（OPEN）
   - `quality.first_pass_rate` → `non_conformance_reports`（OPEN/UNDER_REVIEW）
   - `production.completion_rate` → `production_orders`（PLANNED/RELEASED/IN_PRODUCTION）
   - `production.delayed_orders` → 逾期 `production_orders`
   - `delivery.delayed_sales_orders` / `sales.open_orders` → 对应 `sales_orders`
   - `finance.collection_rate` → 未收清 `sales_invoices`
   - `finance.payable_open` → `supplier_invoices`（CONFIRMED）
   - `progress.avg_completion_rate` → `production_progress`（完成率偏低工序）
   - 无证据的告警直接丢弃（验收 #2）。
4. MRP 异常：仅当 `role in INTENT_REGISTRY["open_mrp_exceptions"].allowed_roles` 时读取 `MrpException`（`resolution_status=OPEN`，`shortage_date` 在窗口内或为空，按 `shortage_qty` 降序，最多 20 条），每条异常生成一个告警；`evidence=[{table:"mrp_exceptions", record_ref:id}]`，`drilldown="/pp/planning-exceptions"`。
5. 金额裁剪：从 `INTENT_REGISTRY["customer_credit_status"].output_fields` 推导可看金额的角色集合（`FINANCE/GENERAL_MANAGER/ADMIN`），其余角色对金额类指标（`finance.payable_open`、`sales.amount_open`）输出 `current_value/threshold/deviation = null`、`amount_masked=true`，模板文本不含金额数字。
6. 归因提示 `attribution`（确定性规则）：OEE 指向最差工作中心及停机小时；NCR 指向设备原因张数；成本指向差异最大类型；逾期指向单据张数；MRP 指向缺料物料与建议。
7. 确定性模板 `narrative`：按严重度排序逐条输出“指标—当前值—阈值—偏离—关联单据数—归因—建议”，全部数字来自结构化告警事实集合。
8. LLM 润色（可选，双重开关 `ai_llm_enabled` + `ai_llm_narration_enabled`）：
   - payload 只含告警元数据与聚合值；`ai_llm_allow_external_data=false` 时剔除任何行级 `record_ref`、单号、物料编码与金额值（金额以 `masked` 标记）。
   - `client.complete({"task":"insight_narration",...})` 仅取文本，不采纳任何结构化判定。
   - 用 `numbers_subset(text, allowed_facts)` 回查；通过则替换模板，否则保留模板。
   - 任何 `LLMError`/异常/空文本都静默降级为模板，不影响接口可用性。
   - 返回 `narration_source` = `template|llm`，`model` = `deterministic-v1` 或 `client.last_model`。

响应结构（保留 `window`/`alerts`，移除 `placeholder`）：

```json

  "generated_at": "...",
  "summary": {"total": 3, "critical": 1, "warning": 2, "info": 0, "truncated": false},
```

### 3. 修改 `backend/api/routers/ai.py`

```python
@router.get("/insights/dashboard")
async def dashboard_insights(
    window: str = Query("7d"),
    current_user: User = Depends(get_current_user),
    db: Session = Depends(get_db),
) -> dict:
    _ensure_chatbi()
    if window not in {"7d", "30d"}:
        _raise_http(AIException("AI_PARAM_INVALID", "window 仅支持 7d / 30d"))
    from backend.services.ai.insights import build_dashboard_insights
    return build_dashboard_insights(db, window, _role_of(current_user))
```

只读：不写 `AiQueryLog`、不写任何业务表。

### 4. 新增 `backend/tests/test_ai_insights.py`

- 空库：200、`alerts == []`、模板提示“未发现异常”、无 `placeholder`。
- 演示数据集：每个 alert 都有非空 evidence 且含 `table/record_ref`；MRP 告警仅在 PLANNER/GENERAL_MANAGER/ADMIN 可见。
- 金额裁剪：SALES_MANAGER/WAREHOUSE 的金额告警 `current_value is None` 且 `amount_masked=True`；FINANCE/ADMIN 可见数值。
- `window=1d` → 422 `AI_PARAM_INVALID`；`AI_CHATBI_ENABLED=false` → 503。
- 只读：调用前后业务表计数一致。
- LLM 降级：monkeypatch `get_llm_client` 返回桩；桩返回含未授权数字 → 保留模板；返回合法数字 → `narration_source="llm"`；抛 `LLMError` → 模板且 200。
- 窗口过滤：30d 能包含 7d 之外的 MRP 异常（直接用 service 函数断言，避免时区/日期脆弱）。
