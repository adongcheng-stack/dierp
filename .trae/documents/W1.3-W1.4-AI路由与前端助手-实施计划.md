## 实施步骤

### 一、W1.3 后端路由

**改 `backend/api/routers/ai.py`**

1. 新增开关检查辅助：
   - `_ensure_enabled()`：`AI_ENABLED=false` → `AIException("AI_DISABLED")`（503）；
   - `_ensure_chatbi()`：在 `_ensure_enabled` 之后再判 `AI_CHATBI_ENABLED` → 503 `AI_CHATBI_DISABLED`。
   - 所有路由（含 `/ping`）在鉴权依赖之后调用；`require_ai_access` 仍由 main.py 路由级依赖先行，保证匿名 401 优先于 503。
2. `POST /chat`（`Depends(get_current_user)` + `Depends(get_db)` + `Request`）：
   - 校验 `body.question` 为非空字符串（否则 422 `AI_PARAM_INVALID`）；
   - 调 `pipeline.ask(question, user, db, request_id=request.state.request_id)`；
   - 捕获 `AIException` → `HTTPException(exc.http_status, detail=exc.to_payload())`。
3. `GET /queries?page=&page_size=`：`AiQueryLog` 按 `is_deleted=False`、`created_at desc`；非 ADMIN 仅本人 `username`；返回 `{items,total,page,page_size}`。
4. `POST /queries/{trace_id}/feedback`：`score ∈ {-1,0,1}`、`comment ≤500`；记录不存在 404；非本人且非 ADMIN 403；写 `feedback_score/feedback_comment` 后 commit。
5. `GET /insights/dashboard?window=7d|30d`：校验窗口；本轮返回占位结构 `{window, alerts: [], placeholder: true}`（W1.5 不在本轮范围，路由需出现在 OpenAPI 以满足 10 条路由验收）。
6. `/ontology/*` 与 `/ping` 增加 `_ensure_enabled()`。

**改 `backend/tests/test_ai_router.py`**（复用现有 fixture）

- OpenAPI 断言设计 §8.1 的 10 条路由全部存在；
- `AI_ENABLED=false`：`/ping`、`/ontology/entities`、`/chat` 均 503 且 `detail.code=AI_DISABLED`；
- `AI_CHATBI_ENABLED=false`：`/chat` 503 `AI_CHATBI_DISABLED`，`/ontology/entities` 仍 200；
- `/chat` 成功链路（复用 `tests/fixtures/ai_demo_dataset.py` + monkeypatch `audit_mod.SessionLocal`）：返回 `answer/data/provenance/limits`，并断言 6 张关键业务表行数前后不变；
- `/queries`：普通用户只看到本人记录，ADMIN 看全部；
- feedback：他人记录 403、本人 200。

### 二、W1.4 前端页面

**新增 `frontend/src/services/ai.ts`**

- 类型：`AiChatResponse / AiProvenance / AiChatError`；
- `ask(question, context?)`、`getQueries(params)`、`sendFeedback(traceId, body)`，复用 `api.ts` 实例。

**新增 `frontend/src/pages/ai/AiAssistantPage.tsx`**

- antd 现成组件（Card/Input.TextArea/Button/Tag/Table/Alert/Empty/Spin/Descriptions/Typography/Space），**不新增依赖**；
- 提问区 + 7 条意图示例（来自 `ai-intents.json` 的 label）；
- 状态：loading（Button/Spin）、空结果（`row_count=0` → Empty/提示）、被拒绝/超时/限流/开关关闭（按 `detail.code` 与 HTTP 状态给中文文案，展示 `trace_id`）；
- 答案区：`answer` + 意图徽标 + 参数；
- 数据区：按 `data.columns` 渲染 Table；
- 溯源区：`provenance[]` 展示实体类/表/记录键；`record_ref` + `downlink` 点击用 `useNavigate` 跳到既有列表页（`/pp/kitting`、`/sd/sales-orders`、`/mm/materials`、`/sd/customers`、`/sd/invoices`、`/qms/ncrs`；`null` 不渲染链接）；
- 限额区：`limits.shacl / coverage / truncated / elapsed_ms / model`；
- 金额列角色裁剪由后端 `output_fields` 负责，前端只按 `data.columns` 渲染。

**改 `frontend/src/App.tsx`**：`const AiAssistantPage = lazy(...)`，新增 `<Route path="/ai" element={<AiAssistantPage />} />`。

**改 `frontend/src/components/layout/menuConfig.tsx`**：`NAV_ITEMS` 在首页后插入 `{ key: '/ai', label: 'AI 助手', icon: Sparkles, path: '/ai' }`。

**改 `frontend/src/components/layout/navSections.ts`**：工作台 keys 改为 `['/', '/ai', 'kpi']`。

**改 `frontend/src/components/layout/navSections.test.ts`**：断言 `/ai` 位于工作台且紧跟 `/`。

### 三、W1.4 mock handlers

**改 `frontend/src/mock/handlers.ts`**

1. `handleMockRequest` 开头：`/ai/` 前缀走独立分发，**跳过通用读写门**（POST `/ai/chat` 不能被写门 403），内部自行 `requireUser` + 角色校验。
2. 新增 `route('GET','/ai/ping')`、`route('POST','/ai/chat')`、`route('GET','/ai/queries')`、`route('POST','/ai/queries/:traceId/feedback')`、`route('GET','/ai/ontology/entities')`、`route('GET','/ai/insights/dashboard')`。
3. `/ai/chat` 使用确定性规则解析（与后端 §7.1.1 同义关键词：缺料/齐套、交付/延期、安全库存、计划异常、信用、应收/未收款、不合格/NCR），拒绝类（删除/修改/新增/导出/所有表/忽略规则）返回 422 `AI_INTENT_UNKNOWN`；按 `ai-intents.json.roles` 做 403 `AI_PERMISSION_DENIED`。
4. 逐意图从 mock db 集合取数（`kittingResults / materials / salesOrders+productionOrders / mrpExceptions / customers+receivableEntries+salesOrders / salesInvoices / nonConformanceReports`），强制 `limit`，生成 `provenance[{table,record_ref,ontology_class}]`，响应结构与后端一致（`trace_id/intent/answer/data/provenance/limits/model`）。
5. 金额列裁剪：`AMOUNT_COLUMNS` 对非 `FINANCE/GENERAL_MANAGER/ADMIN` 从 columns/rows 剔除，保证 WAREHOUSE vs FINANCE 差分。
6. 无匹配返回 200 + `row_count=0` + "未找到符合条件的结果。"。

**改 `frontend/mock-tests/handlers.spec.ts`**：新增 AI 冒烟（匿名 401 / WAREHOUSE 问信用 403 / PLANNER 齐套 200 且含 provenance / 金额列按角色差分 / 空结果）。

**改 `frontend/scripts/check-mock-rbac.mjs`**：新增 3 条 AI 用例（匿名 401 / 越权 403 / 合法 200）。

### 四、契约一致性（评审 S4）

- 生成 `frontend/mock-tests/ai-golden.json`：对 13 条验收问题记录 `{intent, params, columns, status}`（由后端 demo fixture 实跑生成，mock 用同一份文件比对）；
- `handlers.spec.ts` 与新增 `backend/tests/test_ai_golden_contract.py` 读取同一文件，分别驱动 mock 与后端，断言四个契约字段一致。
- **已知偏差（如实标注）**：`row_count` 不纳入 golden，因为 mock 演示库与后端 fixture 是两套数据集（设计 §10 只要求契约一致、行内容可不同）。拒绝类用例另断言 `status/row_count=0`。
