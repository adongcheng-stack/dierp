## 1. 现状盘点（为什么要做）

| 事实 | 位置 | 后果 |
|---|---|---|
| 库存只有 `current_stock` 数量字段 | `backend/common/models/mm.py:20` | 无法回答「当前库存值多少钱」 |
| 标准成本按 BOM 卷算，作为唯一计价依据 | `backend/services/planning/cost_engine.py` `rollup_standard_cost` | 采购价波动、供应商折让完全不进入成本 |
| 库存变动点散落 **7 处**直写 `current_stock` | mm 领料(419)/盘点(883)、pp 完工(991)、purchase 到货(255)/退货(1330)、sd 发货(3416)/取消(3493) | 改造必须逐一收口，漏一处就数量/金额账不平 |
| GL 8 个业务事件的金额口径均为「数量×标准成本」 | `backend/services/finance/gl_rules.py` + 各路由 `gl_post` 调用 | 出库成本与真实入库成本脱节，毛利失真 |
| 期初没有建账分录 | 设计 §5.3 注明 demo 口径未做 | 移动加权需期初数量×单价的金额，必须先补建账 |
| `MaterialTransaction` 有流水但无成本快照 | `mm.py:92` 起 | 红字冲回只能按当前均价，历史出库成本无法溯源 |

## 2. 目标与非目标

**目标**

1. 每种物料维护一条估值记录：`qty / amount / avg_cost / last_cost`，数量与金额同步变动
2. 所有 7 个库存变动点通过**单一写入口**操作，杜绝散落直改
3. 出库必须写**成本快照**（当时单价、当时余额），红字冲回按原快照而非当前均价
4. GL 的出库类分录（SALES_DELIVERY_SHIPPED / MATERIAL_ISSUE / PRODUCTION_COMPLETE 等）金额改取移动加权成本
5. 提供可审计的估值余额表 + 成本差异归属

**非目标（本批明确不做）**

- 分仓库存金额（调拨仍是纯流水、总量不变，金额账不动）——与 P3「不迁移仓库字段」一致
- 标准成本法/移动加权法切换开关（本批直接切换，标准成本仅作为期初和无价入库的回退）
- 历史单据逐笔回补（沿用 demo 口径：只对当前结存建期初，不回溯）
- 月末一次加权、先进先出等其他计价法

## 3. 领域模型变更

新增 2 实体（走 planning.yaml → generate_models → create_all → alembic 既有链路）：

### 3.1 `InventoryValuation` 库存估值（table `inventory_valuations`，top_category EventRecord）
| 字段 | 类型 | 说明 |
|---|---|---|
| `material_code` | string(50) unique FK materials | 物料（一物料一行） |
| `qty` | decimal(15,2) | 当前结存数量（与 `Material.current_stock` 对齐） |
| `amount` | decimal(18,4) | 当前结存金额（**不允许为负**，见 §4.4） |
| `avg_cost` | decimal(18,6) | 移动加权单价 = amount / qty（qty=0 时保留 last_cost） |
| `last_cost` | decimal(18,6) | 最近一次入库单价（qty=0 时的计价回退） |
| `updated_at` | datetime | 最后变动时间 |

### 3.2 `ValuationMove` 估值流水（table `valuation_moves`，top_category EventRecord）
| 字段 | 类型 | 说明 |
|---|---|---|
| `move_number` | string(50) unique index | 流水号（VM-YYYYMMDD-XXXX，遵循坑 9 前缀规划） |
| `material_code` | string(50) index FK | 物料 |
| `direction` | enum `ValuationDirection` IN/OUT | 方向 |
| `qty` / `unit_cost` / `amount` | decimal | 数量、本次单价、本次金额 |
| `balance_qty` / `balance_amount` | decimal | 变动后余额（审计快照） |
| `source_type` / `source_ref` | string | 业务事件与单据号（与 GL 事件同源） |
| `reversal_of` | string(50) nullable | 红字冲回指向的原流水号（关键：红冲按原成本） |

### 3.3 枚举
- `ValuationDirection`: `IN / OUT`
- `CostSourceType`: `PURCHASE_RECEIPT / PURCHASE_RETURN / PRODUCTION_COMPLETE / MATERIAL_ISSUE / SALES_ISSUE / SALES_RETURN / STOCKTAKE / OPENING / TRANSFER`

## 4. 算法与业务口径

### 4.1 核心公式（全部用 Decimal，quantize 到 0.000001，`ROUND_HALF_UP`）

```
入库：amount += qty × unit_cost；qty += qty；avg_cost = amount / qty
出库：cost = 本次 qty × 当前 avg_cost（若 qty=0 用 last_cost）
      amount -= cost；qty -= qty；avg_cost 不变（除非 qty=0）
红冲：按原 ValuationMove.unit_cost 反向入账（不按当前均价）
余额守护：出账后 amount < 0 → 差额记入成本差异科目，amount 钳制为 0，写告警日志
```

### 4.2 七个库存变动点的口径表

| 变动点 | 方向 | unit_cost 来源 | 金额/成本处理 |
|---|---|---|---|
| 采购到货 | IN | 采购单行 `unit_price`（不含税口径 demo 统一按发票额） | GL SUPPLIER_INVOICE_CONFIRMED 口径不变，估值按收货价 |
| 采购退货 | OUT | 当前 avg_cost | 红冲场景按原收货流水价（有 `reversal_of`） |
| 完工入库 | IN | 工单实际单位成本 `ProductionCost.total_actual / quantity`；缺失回退标准成本并告警 | GL PRODUCTION_COMPLETE 金额改取此值 |
| 生产领料 | OUT | 当前 avg_cost | GL MATERIAL_ISSUE 金额改取此值；同时写入 `ProductionCost.material_cost_actual` |
| 销售发货 | OUT | 当前 avg_cost | GL SALES_DELIVERY_SHIPPED 金额改取此值；发货明细存成本快照 |
| 销售取消 | IN | 原发货快照单价 | 红冲按原成本入账，GL 红字分录同步 |
| 盘点调整 | IN/OUT | 当前 avg_cost（无库存用 last_cost/标准成本） | 差额进成本差异科目；GL STOCK_ADJUST 金额取差异 |

> 调拨（TRANSFER）：demo 不分仓，数量一出一进抵消，金额账不动，仅记 ValuationMove 两条（OUT/IN 同单价）供审计。

### 4.3 单一写入口（关键架构决策）

新增 `backend/services/inventory/valuation.py`：

```python
class InventoryValuationService:
    @staticmethod
    def post(db, *, material_code, qty_delta, unit_cost, source_type, source_ref,
             reversal_of=None, operator="system") -> ValuationMove:
        """唯一库存写入口：校验 → 算成本 → 更新估值 → 写快照流水 → 返回 move"""
```

**7 处改造**（去散落化）：`mm.py` 领料/盘点、`pp.py` 完工、`purchase.py` 到货/退货、`sd.py` 发货/取消；删除这些路由里的 `material.current_stock ±=` 直写，改为调用 service。service 同时更新 `Material.current_stock`，保证数量账仍只有一处真相。

### 4.4 异常与边界
- 出库数量 > 当前 qty → 400（沿用现有库存不足校验，service 再兜底一次）
- 出账后 amount < 0 → 钳制 0 + 差额写 `CostVariance` + 告警日志（不允许负库存金额）
- qty=0 时 avg_cost 保留 last_cost，避免除零
- 红冲找不到原流水 → 回退当前 avg_cost + 告警，不静默失败
- 所有操作在同一 DB 事务内，估值/数量/流水/GL 分录要么全成要么全回滚

## 8. 回滚与风险

- 回滚：新表可 drop；7 处路由改造通过 git revert 单提交回退；数据量小（demo），无生产迁移风险
- 风险 1：7 处漏改 → 靠**全量 grep `current_stock ±=` 归零** + 冒烟覆盖 7 事件拦截
- 风险 2：金额账与数量账漂移 → 每次变动后校验 `round(avg_cost × qty, 2) == round(amount, 2)`（qty>0）
- 风险 3：红冲按错成本 → 强制 `reversal_of` 快照校验，探针覆盖「发货→价格变动→取消」场景
- 风险 4：期初口径争议（标准成本 vs 最近采购价）→ 本期用标准成本并标注，待确认后可换
