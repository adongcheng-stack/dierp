# 某某ERP系统 - 用户故事（User Stories）

## 文档说明

**版本：** v1.4  
**创建日期：** 2025-12-12  
**最后更新：** 2025-01-XX

本文档描述了某某ERP系统的用户故事，采用敏捷开发中常用的用户故事格式。每个用户故事包含角色、功能、价值和验收标准，帮助开发团队理解用户需求并指导开发工作。

---

## 一、用户故事格式说明

### 1.1 标准格式

```
As a [角色]
I want [功能]
So that [价值]

验收标准：
- Given [前置条件]
- When [操作]
- Then [预期结果]
```

### 1.2 优先级说明

- **P0（关键）**：核心功能，必须实现
- **P1（高）**：重要功能，建议优先实现
- **P2（中）**：一般功能，可以后续实现
- **P3（低）**：辅助功能，可选实现

## 二、销售与分销模块（SD Module）

### 2.1 客户管理

#### US-SD-001: 创建客户

**用户故事：**
```
As a 销售员
I want 创建新客户并填写完整的客户信息（包括地址、联系人、合作属性等）
So that 我可以管理客户档案，为后续的报价和订单提供基础数据
```

**优先级：** P0  
**验收标准：**
- Given 销售员已登录系统
- When 销售员填写客户基本信息（客户ID、公司名称等）并保存
- Then 系统创建客户记录，状态为DRAFT
- And 销售员可以添加多个地址、联系人和合作属性
- And 系统验证客户ID唯一性

**相关用例：** UC-SD-001

---

#### US-SD-002: 审批客户

**用户故事：**
```
As a 销售经理
I want 审批新创建的客户
So that 确保客户信息的准确性和合规性，只有审批通过的客户才能用于业务
```

**优先级：** P0  
**验收标准：**
- Given 客户状态为PENDING_APPROVAL
- When 销售经理审批通过
- Then 客户状态更新为ACTIVE
- And 只有ACTIVE状态的客户才能创建报价单和销售订单

**相关用例：** UC-SD-002

---

#### US-SD-003: 创建本厂编号映射

**用户故事：**
```
As a 销售员/工程师
I want 创建客户的本厂编号与系统内部物料编码的映射关系
So that 在创建销售订单时，系统可以自动识别物料和生产版本
```

**优先级：** P0  
**验收标准：**
- Given 客户和物料已存在
- When 销售员创建本厂编号映射（客户ID + 本厂编号 → 物料编码 + 生产版本）
- Then 系统保存映射关系
- And 创建销售订单时，系统可以根据客户ID和本厂编号自动查找映射
- And 同一客户的本厂编号在同一时间段内唯一

**相关用例：** UC-SD-003

---

### 2.2 报价单管理

#### US-SD-004: 创建报价单

**用户故事：**
```
As a 销售员
I want 为客户创建报价单，包含产品信息、数量和价格，并计算报价明细成本
So that 我可以向客户提供正式报价，促进订单成交
```

**优先级：** P0  
**验收标准：**
- Given 客户状态为ACTIVE
- When 销售员创建报价单并填写产品信息（本厂编号、产品名称）
- Then 如果本厂编号对应的产品主数据不存在，SD模块调用ENG模块API自动创建产品主数据，自动创建的产品主数据不需要审核
- And 销售员填写板规格参数、工艺参数、加价选项
- And 销售员点击"计算报价"按钮手动计算报价明细成本
- Then 系统计算报价明细成本（交货面积、成本/平米、成本PCS、报价价格、工程费、板材费、测试架费用等），并生成工序成本明细
- And 系统创建报价单记录，状态为DRAFT
- And 销售员可以添加报价单明细

**相关用例：** UC-SD-004

---

#### US-SD-005: 提交报价单审批

**用户故事：**
```
As a 销售员
I want 提交报价单进行审批
So that 报价单可以经过销售、财务、总经理的审批流程，确保价格合理
```

**优先级：** P0  
**验收标准：**
- Given 报价单状态为DRAFT
- When 销售员提交审批
- Then 系统创建工作流实例
- And 报价单状态更新为PENDING_SALES
- And 销售经理可以审批报价单

**相关用例：** UC-SD-005

---

#### US-SD-006: 审批报价单

**用户故事：**
```
As a 销售经理/工程师/客户经理或总经理
I want 审批报价单（三级审核流程，串行）
So that 确保报价单的价格和条款符合公司政策
```

**优先级：** P0  
**验收标准：**
- Given 报价单已提交审批
- When 一级审核（销售经理SALES_MANAGER）审批通过
- Then 系统移动到二级审核节点（工程师ENGINEER）
- When 二级审核（工程师ENGINEER）审批通过
- Then 系统移动到三级审核节点（客户经理ACCOUNT_MANAGER或总经理GENERAL_MANAGER）
- When 三级审核审批通过
- Then 报价单状态更新为APPROVED，进入"销售员经客户确认"状态
- And 如果任何一级审核被拒绝，报价单状态更新为DRAFT（退回草稿状态），退回操作记录审核历史，保存退回原因

**相关用例：** UC-SD-006

---

#### US-SD-007: 重新提交被拒绝的报价单

**用户故事：**
```
As a 销售员
I want 修改被拒绝的报价单并重新提交
So that 我可以根据审批意见调整报价，重新进入审批流程
```

**优先级：** P1  
**验收标准：**
- Given 报价单状态为DRAFT（退回草稿状态）
- When 销售员（SALES角色）修改报价单并重新提交
- Then 系统清除之前的审批信息
- And 报价单状态更新为待一级审核（PENDING_SALES）
- And 报价单重新进入三级审核流程（串行）

**相关用例：** UC-SD-008

---

#### US-SD-009: 销售员经客户确认报价单

**用户故事：**
```
As a 销售员
I want 与客户确认报价单并在系统中标记客户确认状态
So that 客户确认后的报价单可以转为销售订单
```

**优先级：** P0  
**验收标准：**
- Given 报价单状态为APPROVED（已通过三级审核）
- When 销售员与客户沟通确认报价单
- And 客户确认报价单（线下确认）
- And 销售员在系统中标记"客户已确认"
- Then 报价单可以转为销售订单
- When 客户不确认报价单
- And 销售员在系统中标记"客户不确认"
- Then 报价单状态更新为DRAFT（退回草稿状态），退回操作记录审核历史，保存退回原因
- And 销售员可以修改报价单并重新提交审核

**相关用例：** UC-SD-009

### 2.3 销售订单管理

#### US-SD-010: 创建销售订单

**用户故事：**
```
As a 销售员
I want 创建销售订单，可以选择关联报价单或直接创建
So that 我可以将客户需求转化为正式订单，启动生产流程
```

**优先级：** P0  
**验收标准：**
- Given 客户状态为ACTIVE
- When 销售员创建销售订单
- Then 系统根据客户ID和本厂编号自动查找FactoryProductMapping
- And 系统自动填充material_code和production_version_id
- And 系统自动计算销售单位、生产单位、转换系数和生产数量
- And 如果是返单，可以选择历史报价单（包括已关联的）
- And 如果是新单，只能选择已批准且未关联的报价单
- And 如果关联了报价单，报价单状态更新为LINKED

**相关用例：** UC-SD-010

---

```
As a 销售员
```

## 三、工程管理模块（ENG Module）

### 3.1 物料管理

#### US-ENG-001: 产品主数据管理

**用户故事：**
```
As an 工程师
I want 创建和维护产品主数据，以本厂编号作为唯一标识
So that 我可以建立完整的产品档案，为BOM、工艺路线等提供基础数据
```

**优先级：** P0  
**验收标准：**
- Given 工程师已登录系统
- When 工程师创建产品主数据并填写完整信息
- Then 系统创建产品主数据记录（只显示成品FG类型的物料）
- And 本厂编号作为唯一标识，同时作为产品编码（material_code）
- And 产品主数据包含产品基本信息、PCB专有工程属性（层数、板厚、铜厚、表面处理等）、技术参数、尺寸信息、供应链计划参数等
- And 如果本厂编号对应的产品不存在，系统提供创建产品的快捷入口
- And ENG模块拥有产品主数据的完整CRUD权限
- And SD模块可以创建（自动创建）、查询、引用产品主数据，但不能修改、删除产品主数据（需ENG模块操作）

**相关用例：** UC-ENG-001

---

#### US-ENG-001A: 产品列表查询

**用户故事：**
```
As an 工程师
I want 查询产品主数据列表
So that 我可以快速找到需要的产品信息
```

**优先级：** P0  
**验收标准：**
- Given 工程师已登录系统
- When 用户输入查询条件（本厂编号、产品名称、产品系列等）
- Then 系统显示符合条件的产品主数据列表（只显示成品FG类型），支持筛选和分页

**相关用例：** UC-ENG-001A

---

```
I want 当生产订单状态变化时，自动同步销售订单状态
So that 销售订单状态可以反映实际的生产进度，销售员可以及时了解订单状态
```

**优先级：** P0  
**验收标准：**
- Given 生产订单已创建并关联销售订单
- When 生产订单状态变化（下达、完成等）
- Then 系统自动检查关联的销售订单
- And 如果所有生产订单都已完成或已关闭，销售订单状态更新为COMPLETED
- And 如果有生产订单在生产中，销售订单状态更新为IN_PRODUCTION
- And 如果所有生产订单都已下达但还未开始生产，销售订单状态保持APPROVED

**相关用例：** UC-PP-004, UC-PP-007相关

---

### 7.2 工作流审批

#### US-CROSS-002: 多部门顺序审批流程

**用户故事：**
```
As a 系统
I want 实现多部门顺序审批流程（销售 → 工程 → 物料 → 财务）
So that 销售订单可以经过各部门的评审，确保订单可执行
```

**优先级：** P0  
**验收标准：**
- Given 销售订单已提交评审
- When 各部门按顺序审批
- Then 系统创建工作流实例（SALES_ORDER_REVIEW）
- And 系统为所有节点创建节点实例（初始状态为PENDING）
- And 只有当前节点可以审批
- And 只有具有相应角色的用户才能审批该节点
- And 所有节点审批通过后，销售订单状态更新为APPROVED
- And 任何一个节点被拒绝，销售订单状态更新为REJECTED

**相关用例：** UC-SD-011, UC-SD-012, UC-SD-013, UC-SD-014, UC-SD-015

## 十一、总结

### 11.1 用户故事特点

1. **以用户价值为中心**：每个用户故事都明确说明了"为什么"（So that），强调用户价值
2. **角色明确**：每个用户故事都指定了具体的角色（As a...）
3. **功能清晰**：每个用户故事都描述了具体的功能（I want...）
4. **验收标准明确**：每个用户故事都有详细的验收标准，便于测试和验收

### 11.2 关键业务流程覆盖

- ✅ 客户管理流程
- ✅ 报价单审批流程
- ✅ 销售订单多部门评审流程
- ✅ 生产订单执行流程
- ✅ 工序报工流程
- ✅ 生产领料流程
- ✅ 工程数据管理流程
- ✅ 状态自动同步机制

### 11.3 开发建议

1. **优先实现P0用户故事**：这些是核心功能，必须首先实现
2. **按模块迭代开发**：建议按照SD → ENG → PP → MM的顺序进行开发
3. **关注跨模块功能**：状态同步、工作流审批等跨模块功能需要特别关注
4. **持续优化**：根据用户反馈，持续优化用户故事和验收标准
