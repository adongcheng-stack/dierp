## 已完成的工作

### 1. 项目架构搭建 ✅
- ✅ 前后端分离架构
- ✅ 后端：Python + FastAPI（微服务架构）
- ✅ 前端：React + TypeScript + Ant Design
- ✅ 数据库：PostgreSQL（SQLAlchemy ORM）
- ✅ 流程引擎：轻量级BPMN引擎

### 2. 数据库模型设计 ✅
- ✅ 用户模型（User，支持角色管理和软删除）
- ✅ SD模块模型（Customer, Quotation, SalesOrder, FactoryProductMapping等）

  - ✅ 报价单模型（支持三级审核流程、已关联状态）
  - ✅ 销售订单模型（支持订单评审、单位转换、本厂编号映射）

- ✅ ENG模块模型（BOM, Routing, MI, ProductionVersion等）
  - ✅ BOM模型（支持PCB专有属性、审计追踪、行号管理）
  - ✅ 工艺路线模型（支持内部/外协/质检工序、生产基础信息）
  - ✅ MI模型（支持指令集列表、审核流程）
  - ✅ 生产版本模型（BOM+工艺路线+MI组合）
- ✅ PP模块模型（WorkCenter, ProductionOrder, OperationReport等）
  - ✅ 工作中心模型（支持调度、产能、成本、PCB技术属性等完整信息）

  - ✅ 工序报工模型

  - ✅ 物料模型（支持PCB专有属性、单位转换、供应链计划等完整信息）

### 3. 核心功能实现 ✅

#### SD模块（销售与分销）
- ✅ 客户管理（创建、查询、列表，支持地址、联系人、合作角色、销售数据等完整信息）
- ✅ 报价单管理（创建、提交审核、审核通过/拒绝、被拒绝后业务员可修改并重新提交）
- ✅ 销售订单管理（创建、列表、订单评审、发货、签收、对账、关闭）
- ✅ 三级审核流程支持（销售→财务→总经办）
- ✅ 订单评审多部门评审流程（支持销售、工程、生产、质量、财务等多个部门并行或串行评审）
- ✅ 本厂编号管理（客户产品编号到物料编码和生产版本的映射）
- ✅ 返单逻辑（支持返单选择历史报价单，新单只能选择已批准报价单）

#### ENG模块（工程管理）
- ✅ BOM管理（创建、查询、列表，支持PCB专有属性、审计追踪、行号管理）
- ✅ BOM基本验证（已实现：父物料存在性检查、BOM编号唯一性、明细不能为空、物料编码存在性检查）
- ⚠️ BOM完整性验证（部分实现：缺少数量合理性、损耗率验证、循环引用检查、层级关系验证等）
- ✅ 工艺路线管理（创建、查询、列表，支持内部/外协/质检工序、生产基础信息）
- ✅ 工艺路线基本验证（已实现：物料存在性检查、Routing ID唯一性、工序不能为空）
- ⚠️ 工艺路线完整性验证（部分实现：缺少工序顺序验证、工作中心有效性、时间参数合理性、业务规则验证等）
- ✅ MI管理（创建、查询、列表、审核，支持指令集列表、基于工艺路线自动生成）
- ✅ 生产版本管理（BOM+工艺路线+MI组合，支持发布功能）

#### PP模块（生产计划与控制）
- ✅ 工作中心管理（创建、查询、列表，支持调度、产能、成本、PCB技术属性等完整信息）
- ✅ 工单管理（创建、下达、开始、完成、关闭，支持生产版本选择）
- ✅ 工序报工（创建、查询、列表，自动排除已完成订单）
- ✅ 生产进度跟踪
- ✅ 工单状态自动同步销售订单状态

#### MM模块（物料管理）

## 使用说明

### 启动后端
```bash
cd backend
pip install -r requirements.txt
python init_db.py  # 初始化数据库
uvicorn api.main:app --reload
```

### 启动前端
```bash
cd frontend
npm install
npm run dev
```

### 模型文件使用说明

#### PlantUML模型文件
- **ER图模型**：`docs/某某ERP系统 - ER图模型.puml`
  - 可在VS Code（安装PlantUML插件）、IntelliJ IDEA、在线工具中打开
  - 在线工具：http://www.plantuml.com/plantuml/uml/

#### ECore模型文件
- **ECore模型**：`docs/某某ERP系统 - ECore模型.ecore`
  - 可在Eclipse（安装EMF插件）中打开
  - 可用于生成Java代码、模型编辑器等
  - 符合EMF规范，支持模型驱动开发

```bash
cd docs
python generate_ecore.py
```
这将从ER模型定义生成完整的ECore模型文件。

### 订单评审多部门评审流程说明

系统支持销售订单的多部门评审流程，确保订单在正式下达前经过各部门的全面评审。

#### 评审流程模式

1. **串行评审模式**
   - 按部门顺序依次评审（销售→工程→生产→质量→财务）
   - 前一个部门评审通过后，才能进入下一个部门评审
   - 任一部门拒绝，评审流程终止，订单返回修改

2. **并行评审模式**
   - 多个部门同时进行评审（如工程、生产、质量可并行）
   - 所有部门评审通过后，订单才能进入下一阶段
   - 任一部门拒绝，评审流程终止

3. **混合评审模式**
   - 部分部门串行，部分部门并行
   - 灵活配置评审流程，适应不同业务场景

#### 评审部门配置

系统支持以下部门的评审：

1. **销售部门评审**
   - 评审客户需求合理性
   - 评审价格和商务条款
   - 评审交货期可行性

2. **工程部门评审**
   - 评审技术可行性
   - 评审BOM和工艺路线完整性
   - 评审技术风险和解决方案

3. **生产部门评审**
   - 评审生产能力
   - 评审生产计划可行性
   - 评审资源需求

4. **质量部门评审**
   - 评审质量要求
   - 评审检验标准
   - 评审质量控制措施

5. **财务部门评审**
   - 评审成本核算
   - 评审付款条件
   - 评审财务风险

#### 评审功能特性

1. **评审状态跟踪**
   - 实时显示每个部门的评审状态（待评审、评审中、已通过、已拒绝）
   - 支持评审进度可视化
   - 记录评审时间节点

2. **评审意见记录**
   - 每个部门可填写评审意见
   - 支持评审结果（通过/拒绝）
   - 拒绝时需填写拒绝原因

3. **评审权限控制**
   - 每个部门只能评审自己负责的部分
   - 支持评审权限分配
   - 支持评审委托功能

4. **评审通知机制**
   - 评审任务自动通知相关人员
   - 支持邮件、系统消息等通知方式
   - 支持评审超时提醒

5. **评审历史记录**
   - 完整记录所有评审历史
   - 支持评审意见查询
   - 支持评审流程追溯

#### 评审流程配置

- 支持按订单类型配置不同的评审流程
- 支持按订单金额配置评审流程（如大额订单需要更多部门评审）
- 支持动态调整评审流程
- 支持评审流程模板管理
