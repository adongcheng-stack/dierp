## 一、优化概述

### 1.1 优化目标

- **减少N+1查询**：使用SQLAlchemy的预加载机制（`joinedload`、`selectinload`）减少数据库查询次数
- **提升查询性能**：通过批量加载关联数据，减少网络往返和数据库负载
- **改善用户体验**：缩短API响应时间

### 1.2 优化策略

1. **使用 `joinedload`**：用于一对一和多对一关系，使用SQL JOIN预加载
2. **使用 `selectinload`**：用于一对多和多对多关系，使用单独的SELECT IN查询
3. **组合使用**：对于嵌套关系，组合使用两种加载策略

## 五、最佳实践

### 5.1 何时使用joinedload

- **一对一关系**：使用 `joinedload`
- **多对一关系**：使用 `joinedload`
- **优点**：单次SQL查询，性能最优
- **缺点**：可能产生大量重复数据（对于一对多关系）

### 5.2 何时使用selectinload

- **一对多关系**：使用 `selectinload`
- **多对多关系**：使用 `selectinload`
- **优点**：避免JOIN产生的重复数据，查询结果更清晰
- **缺点**：需要额外的SELECT查询

### 5.3 嵌套关系优化

对于嵌套关系（如：Routing -> Operations -> WorkCenter），使用组合加载：

```python
query = query.options(
    selectinload(Routing.operations).joinedload('work_center')
)
```

### 5.4 性能权衡

- **如果响应模型不需要关联数据**：不要预加载，避免不必要的查询
- **如果关联数据很大**：考虑使用延迟加载或分页加载
- **如果查询频率很高**：考虑使用缓存

## 六、注意事项

### 6.1 模型关系定义

部分模型中的关系被注释掉了（避免循环依赖），这些关系无法使用预加载。如果需要预加载这些关系，需要：

1. 取消注释关系定义
2. 使用 `lazy='select'` 或 `lazy='joined'` 配置关系加载策略
3. 或者使用显式JOIN查询

### 6.2 内存使用

预加载会增加内存使用，特别是对于大数据集。建议：

- 使用分页限制返回数量
- 只预加载必要的关联数据
- 对于非常大的数据集，考虑使用延迟加载

### 6.3 查询性能监控

建议添加查询性能监控：

```python
import logging
from sqlalchemy import event
from sqlalchemy.engine import Engine

logger = logging.getLogger("sqlalchemy.engine")

@event.listens_for(Engine, "before_cursor_execute")
def receive_before_cursor_execute(conn, cursor, statement, parameters, context, executemany):
    context._query_start_time = time.time()

@event.listens_for(Engine, "after_cursor_execute")
def receive_after_cursor_execute(conn, cursor, statement, parameters, context, executemany):
    total = time.time() - context._query_start_time
    if total > 0.1:  # 记录超过100ms的查询
        logger.warning(f"Slow query ({total:.2f}s): {statement[:200]}")
```

## 七、后续优化建议

### 7.1 数据库索引优化

确保所有外键字段和常用查询字段都有索引：

```sql
-- 示例：为常用查询字段添加索引
CREATE INDEX idx_sales_orders_customer_status ON sales_orders(customer_id, status);
CREATE INDEX idx_production_orders_sales_status ON production_orders(sales_order_number, status);
```

### 7.2 查询结果缓存

对于不经常变化的数据，考虑使用缓存：

```python
from functools import lru_cache
from datetime import timedelta

@lru_cache(maxsize=1000)
def get_material(material_code: str, cache_time: float):
    # 使用cache_time作为缓存键的一部分，实现TTL
    pass
```

### 7.3 批量查询优化

对于需要批量查询的场景，使用 `in_()` 替代循环查询：

```python
# 不推荐：循环查询
for order_number in order_numbers:
    order = db.query(SalesOrder).filter(SalesOrder.order_number == order_number).first()

# 推荐：批量查询
orders = db.query(SalesOrder).filter(SalesOrder.order_number.in_(order_numbers)).all()
```

### 7.4 分页优化

对于大数据集，使用游标分页替代偏移分页：

```python
# 偏移分页（大数据集性能差）
query = query.offset(skip).limit(limit)

# 游标分页（推荐）
query = query.filter(SalesOrder.id > last_id).limit(limit)
```
