### 1.2 追溯图定义（唯一规则，两侧同构）

**节点类型**：SALES_ORDER / PRODUCTION_ORDER / LOT / MATERIAL / MATERIAL_ISSUE / OPERATION_REPORT / INSPECTION / NCR / EQUIPMENT_FAILURE / PURCHASE_ORDER / CUSTOMER

**正向（从 LOT 出发，深度≤4）**：
1. LOT → PRODUCTION_ORDER（lot.production_order_number）
2. PRODUCTION_ORDER → SALES_ORDER → CUSTOMER
3. PRODUCTION_ORDER → MATERIAL_ISSUE（用料）
4. PRODUCTION_ORDER → OPERATION_REPORT（良品/报废）
5. OPERATION_REPORT/LOT → INSPECTION（按 lot/material）
6. INSPECTION/LOT → NCR → EQUIPMENT_FAILURE（equipment_cause）

**反向（从 物料 或 销售订单/工单 出发）**：
1. MATERIAL → MATERIAL_ISSUE → PRODUCTION_ORDER → LOT
2. MATERIAL → PURCHASE_ORDER_LINE → PURCHASE_ORDER → 供应商
3. PRODUCTION_ORDER/LOT → 上游同正向 3–6

## 4. 附录

### 4.1 架构决策记录（ADR-20261118-01）
追溯能力实现为**只读派生查询引擎**，不新增实体、不写库。理由：追溯图完全可由既有单据链接推导；入本体需要为「查询」发明实体，违反单一事实源原则。原料批次级追溯（需 MaterialIssue 增列 + 迁移）列为 P2 后续项，须人工在场执行。

### 4.2 节点/边字段（两侧同构契约）
`node = {key, type, title, status, quantity, time, meta}`；`edge = {from, to, label}`；响应 `{root, direction, nodes[], edges[], truncated}`。

### 4.3 时间预算
M-1 ≤ 4h；M-2 ≤ 2.5h；M-3 弹性。任一里程碑超时 1.5 倍即降级到 M-3。

### 4.4 接线点回退清单
`backend/api/main.py`（删 2 行）、`backend/services/planning/__init__.py`（删 2 行）、`frontend/src/components/layout/menuConfig.tsx`（删 1 组）、`frontend/src/App.tsx`（删 3 行）、`frontend/src/mock/handlers.ts`（删 QMS 段落后新增段）、`snapshot.json` version 回写。
