# DIERP 计划与控制系统 · 10 分钟端到端演示脚本

| 项目 | 内容 |
|---|---|
| 面向对象 | 演示者 / 销售工程师 |
| 演示主线 | 报价 → 订单 → 工程数据 → 计划闭环 → 生产执行 → 成本 → APS 排程 → 设备管理 → 质量管理 |
| 核心话术 | "从一张报价单出发，系统自动回答：生产什么、什么时候、缺什么料、花多少钱、设备扛不扛得住" |
| 适用环境 | `npm run dev:mock`（演示快照）与 `npm run dev`（真实后端）均可走通，个别差异已标注 |

**演示前检查**：

- 登录账号 `admin / admin123`；
- mock 演示：打开后数据来自内置快照（version 9），刷新页面即恢复；若数据被演示操作改乱，点右上角头像 →「重置演示数据」即可（或控制台执行 `localStorage.removeItem('dierp-demo-db-v1')` 后刷新）；
- 真实后端：先执行 `python backend/upgrade_planning.py`（幂等种子）与 `python backend/scripts/refresh_planning_demo.py`，确保 MPS/MRP/齐套/成本/APS/EAM/QMS 演示数据齐备；演示多轮后点右上角头像 →「清理演示数据」，或在终端执行 `python backend/scripts/reset_demo.py` 一键恢复。

## 场景 0 · 开场（30 秒）

| 项 | 内容 |
|---|---|
| 页面路径 | `/`（仪表盘） |
| 操作动作 | 登录后停留仪表盘，指向「销售/生产/库存/成本」概览数字 |

| 讲解要点 | 制造 ERP 的价值不在记录数据，而在让每个部门在同一个数字口径下做决定——这就是我们今天要演示的主线。 |

## 场景 3 · 计划闭环：MPS → MRP → 计划订单 → 齐套 → 异常（2.5 分钟，核心）

| 步骤 | 页面路径 | 操作动作 | 预期结果 | 讲解要点 |
|---|---|---|---|---|
| 3.1 | `/pp/mps` | 打开 `MPS-20261117-001`，看按周桶的毛需求/净需求/计划接收 | 36 行 MPS 计划行，状态已下达 | 主计划把销售订单+预测合并成一个可执行的生产节奏。 |

> 两种环境均可走通：mock 内置轻量 MRP 运算，演示时甚至可以现场点「运行 MRP」重新计算（30 秒内出结果）；真实后端由 `smoke_planning.py` 验证的同构引擎驱动。

## 场景 5 · 成本引擎（1.5 分钟）

| 步骤 | 页面路径 | 操作动作 | 预期结果 | 讲解要点 |
|---|---|---|---|---|
| 5.1 | `/cost/workbench` | 打开成本工作台总览 | 标准成本/工单成本/差异/结算汇总 | 成本不是月底算账，是每个工单实时归集。 |
| 5.2 | `/cost/standard` | 选成品 `HF1004ENIGAB01` 点「标准成本滚动」 | 按最新 BOM+工艺费率生成/更新标准成本（材料+人工+制费） | 改一个 BOM 用量或费率，标准成本一键重卷——报价再也不用拍脑袋。 |

## 场景 6 · APS 高级排程（2 分钟，压轴亮点一）

| 步骤 | 页面路径 | 操作动作 | 预期结果 | 讲解要点 |
|---|---|---|---|---|
| 6.1 | `/aps/workbench` | 打开 APS 工作台：统计卡 + 产能甘特图 | 打开即有排程结果：工单按工作中心分条，时间轴带刻度 | 有限产能排程：班次×利用率×机器数全在约束里，不是把任务排到天上。 |
| 6.2 | 同页 | 点「运行排程」，选正排 + 生产订单来源，确认 | 30 秒内生成新批次：12 道工序、若干异常，甘特图刷新 | 排程是可重复运算的：需求变了重跑一次，不用人肉重排。 |
| 6.3 | 同页 | 点「插单模拟」，选 INSERT_ORDER | 列出受影响工序、每道工序延期天数与影响级别 | 销售问"这单能插吗"，系统 10 秒给出冲击面——这就是承诺交期的底气。 |
| 6.4 | `/aps/exceptions` | 看六类排程异常：产能超载/交期风险/缺料/技能不匹配/换产超限/资源停机 | PO-APS-04 因交期仅 1 天必现「交期风险」；PO-APS-01/04 有「缺料风险」 | 异常分六类、带建议动作，排产员照单处理。 |
| 6.5 | `/aps/runs` | 对已完成的批次点「发布」 | 批次状态 PUBLISHED，工序转为已发布 | 排程发布即生产指令，与报工进度天然衔接。 |

> 两种环境均可走通：mock 用同构轻量算法预置了排程结果（打开即有甘特），现场重跑/插单/发布均可操作；真实后端由 `smoke_aps_api.py` 全链路验证。

## 场景 7 · 设备管理 EAM（1 分钟，压轴亮点二）

|---|---|---|---|---|

## 收尾话术（30 秒）

> 今天您看到的是一条完整链路：**一张报价单进来，系统告诉您生产什么（MPS/MRP）、缺什么料（齐套/异常）、什么时候能交（APS 排程）、做下来赚不赚钱（成本）、设备扛不扛得住（EAM/OEE）、质量守不守得住（QMS/NCR）**。
> 所有环节共用一套模型与本体：枚举、实体、约束只有一个事实源，改一处全局生效。
> 这不是一个记台账的 ERP，而是一个**能算、能排、能追溯**的计划与控制系统。

## 附：演示应急预案

| 状况 | 处置 |
|---|---|
| mock 数据被改乱 | 右上角头像 →「重置演示数据」；或控制台执行 `localStorage.removeItem('dierp-demo-db-v1')` 后刷新 |
| 真实后端数据缺失 / 多轮演示后数据堆积 | 右上角头像 →「清理演示数据」（仅管理员）；或执行 `python backend/scripts/reset_demo.py`，自动清运行时数据并重建排程批次 + 插单场景 |
| APS 甘特为空 | 先在 APS 工作台点「运行排程」生成批次，或执行 `reset_demo.py` 直接重建已发布批次 |
| OEE 性能率偏低 | 正常：性能率 = 标准工时 ÷ 实际工时，演示报工的实际工时高于标准工时即体现效率损失（DRILL-B ≈ 42%）；无报工数据时按 1 计 |
| 登录失败 | mock 模式任意账号按 `admin/admin123` 即可；真实后端确认账号已初始化 |
