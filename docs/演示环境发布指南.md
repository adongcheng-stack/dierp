# DIERP 演示环境发布指南（dist-demo 静态发布）

本指南说明如何把 DIERP 前端演示包（mock 模式静态产物）发布到任意静态托管环境，供客户演示、试用或内部分发。

| 项目 | 内容 |
|---|---|
| 产物目录 | `frontend/dist-demo` |
| 构建命令 | `cd frontend && npm run build:mock` |
| 特点 | 无需后端、无需数据库，纯静态文件；数据存浏览器 localStorage |
| 登录 | 任意用户名按 `admin / admin123`（mock 鉴权格式为 `Bearer mock.<username>`，仅演示用） |

---

## 1. 产物说明

`npm run build:mock` 执行 `tsc && vite build --mode mock`，产物落在 `frontend/dist-demo/`：

```text
dist-demo/
├── index.html            入口（内联 hash 路由，直接双击可打开）
└── assets/
    ├── index-*.css       样式
    ├── index-*.js        应用入口 + 路由（页面按需懒加载）
    ├── react-vendor-*.js React / Router 基础库
    ├── antd-*.js         antd 组件库
    ├── rc-*.js           rc-* / cssinjs 组件底层
    ├── antd-table-*.js   表格（唯一可独立拆分的 antd 大组件）
    └── <页面>-*.js       各业务页面 chunk（按访问加载）
```

关键配置（`frontend/vite.config.ts`）：

- mock 模式 `base: './'` —— 全部资源按**相对路径**引用，可部署在任意子路径（如 `https://host/demo/dierp/`），也可直接 `file://` 双击打开；
- 路由使用 **HashRouter**（`#/eam/workbench` 形式），刷新/分享链接不会 404；
- 路由级 `React.lazy` + `manualChunks` 分层分包：首屏只加载布局与工作台，vendor 按依赖层次拆分，单个 chunk 均 < 500KB；
- mock 引擎内置与真实后端同构的轻量算法（MPS/MRP/齐套/成本/APS 排程/EAM 到期生成/OEE），写操作实时写入 localStorage。

> 注意：`npm run build`（非 mock）产物在 `dist/`，`base: '/'`，需要真实后端，**不要**与 dist-demo 混用。

## 2. 发布方式

### 2.1 任意静态服务器 / 对象存储

把 `dist-demo/` **整个目录**原样上传即可（保持 index.html 在根）：

- Nginx / Apache / IIS 静态站点；
- 阿里云 OSS / 腾讯云 COS / 七牛 等 OSS 静态网站托管（开启 index.html 默认首页）；
- GitHub Pages / 内网文件服务器。

无任何服务端要求，无需 Node / 数据库。

### 2.2 Nginx 配置示例

```nginx
server {
    listen       80;
    server_name  demo.example.com;

    # 演示包根目录（即 dist-demo 的内容）
    root /var/www/dierp-demo;
    index index.html;

    # 静态资源带 hash 文件名，可长缓存
    location /assets/ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # HashRouter 下无需 try_files 兜底，但配置上无害且可兼容未来路径变更
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 建议关闭演示站缓存，避免升级后浏览器仍用旧 index.html
    location = /index.html {
        add_header Cache-Control "no-cache";
    }
}
```

部署步骤：

```bash
# 1) 本地构建
cd frontend && npm run build:mock

# 2) 上传（示例）
scp -r frontend/dist-demo/* user@demo.example.com:/var/www/dierp-demo/
```

### 2.3 本地快速预览

```bash
cd frontend
npm run build:mock
npx serve dist-demo        # 或 python -m http.server -d dist-demo 8080
# 浏览器打开 http://localhost:3000（serve 默认端口以提示为准）
```

也可以不解包直接体验开发版：`cd frontend && npm run dev:mock`（vite mock 模式，端口 3100）。

## 3. 浏览器数据说明（localStorage）

演示数据全部保存在浏览器 localStorage，**不回传任何服务器**：

| 项 | 值 |
|---|---|
| 存储键 | `dierp-demo-db-v1` |
| 当前快照版本 | `9` |
| 数据内容 | 客户/报价/订单、BOM/工艺、MPS/MRP/计划订单/齐套/异常、工单/LOT/报工（含工艺关联与工时）、标准成本/差异/结算、APS 排程批次/工序/异常/模拟、EAM 维护计划/工单/故障、QMS 检验单/不合格品记录 |
| 首次打开 | 从内置快照初始化并写入 localStorage |
| 后续打开 | 直接读取 localStorage（含您演示时的所有写操作） |

**重置入口**（任选其一）：

- 页面右上角头像 →「重置演示数据」（mock 模式所有账号可用）；
- 浏览器控制台执行：`localStorage.removeItem('dierp-demo-db-v1'); location.reload();`
- 清除该站点站点数据（设置 → 隐私 → 清除站点数据）。

重置后刷新页面即恢复出厂演示数据。

> 真实后端（`npm run dev`）下同一菜单显示为「清理演示数据」，仅管理员可见；它只清空排程/场景/维护/故障等运行时数据并重建一套演示场景，订单、BOM、工艺路线等主数据不受影响。命令行等价入口：`python backend/scripts/reset_demo.py`。

## 4. 版本升级

快照结构变化时 `frontend/src/mock/snapshot.json` 的 `version` 字段必须递增（当前 `9`）：

- `db.ts` 读取时校验 `localStorage` 里的 `version` 与快照一致，**版本不一致即自动丢弃旧数据、回落新快照**；
- 因此每次注入新的演示数据（如 `node frontend/scripts/seed_eam_demo.cjs`），务必同步把 version 加一，否则老用户浏览器里的旧数据不会刷新；
- 静态升级时替换 `dist-demo` 全部文件即可，无需任何迁移。

版本历史：

| version | 内容 |
|---|---|
| 2 | P0 计划闭环演示数据 |
| 4 | P1 成本 + APS 排程演示数据 |
| 5 | P1 EAM 设备管理演示数据（维护计划/工单/故障 + RES-DRILL-B-01 保养联动） |
| 6 | 报工补齐工艺关联与工时（OEE 性能率可计算）；EAM 页可直接展示真实效率差异 |
| 7 | P1 QMS 质量管理演示数据（3 检验单 / 2 不合格品记录 + 报工→NCR、NCR→EAM 双向联动） |

| 9 | P2 双向追溯上线（只读派生查询，无新增集合）：补齐 PO-APS-01..04 的销售订单关联，销售订单可展开 4 张 APS 工单 |

## 5. 常见问题（FAQ）

**Q1：升级后打开还是旧数据？**
浏览器 localStorage 里的快照 version 与新包一致时旧数据会被继续使用。确认新包 version 已递增；若被误改，让用户手动重置（见第 3 节）。`index.html` 可能被浏览器/CDN 缓存，发布时建议对 index.html 设置 `Cache-Control: no-cache`。

**Q2：双击 index.html 打开白屏？**
确认是 `dist-demo`（`base: './'`）而不是 `dist`；用现代浏览器（Chrome/Edge 90+）；不要用 IE。

**Q3：演示中数据被改乱怎么办？**
mock 模式点右上角头像 →「重置演示数据」；真实后端用「清理演示数据」或 `python backend/scripts/reset_demo.py`。演示动线建议每场演示前重置一次。

**Q4：能连真实后端演示吗？**
可以。`cd frontend && npm run dev`（代理 `/api` 到 `localhost:8000`），后端先执行 `python backend/upgrade_planning.py` 等种子脚本。演示多轮后执行 `python backend/scripts/reset_demo.py` 可把排程/场景/EAM 运行时数据恢复到演示初始态（只清运行时数据，不动订单/BOM/工艺）。两套模式的演示动线见《演示脚本-10分钟.md》。

**Q5：登录不上？**
mock 模式固定使用 `admin / admin123`（token 为 `Bearer mock.<username>`，仅演示用）；真实后端需先初始化用户。

**Q6：局域网同事访问不了？**
`npx serve dist-demo` 默认只监听本机，用 `npx serve -l 8080 dist-demo` 并放行防火墙端口；正式演示建议直接部署 Nginx/OSS。

**Q7：文件上传到 OSS 后点刷新 404？**
HashRouter 不会出现路径 404；若出现，说明误用了 `dist`（browser 路由）产物，请改用 `dist-demo`。
