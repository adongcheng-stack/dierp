# 全流程数据结构改进方案实施总结

## 实施日期
2025-12-10

## 实施内容

### 1. 数据模型改进

#### 1.1 新增本厂编号映射模型
- **文件**: `backend/common/models/sd.py`
- **模型**: `FactoryProductMapping`
- **功能**: 建立本厂编号到物料编码和生产版本的映射关系
- **关键字段**:
  - `customer_id`: 客户ID
  - `factory_product_number`: 本厂编号
  - `material_code`: 物料编码
  - `production_version_id`: 生产版本ID（可选）
  - `is_default`: 是否为默认映射
  - `effective_date`: 生效日期
  - `expiry_date`: 失效日期

#### 1.2 增强销售订单模型
- **文件**: `backend/common/models/sd.py`
- **模型**: `SalesOrder`
- **新增字段**:
  - `material_code`: 物料编码（从本厂编号映射获取）
  - `production_version_id`: 生产版本ID（从本厂编号映射获取）
  - `sales_unit`: 销售单位
  - `production_quantity`: 生产数量
  - `production_unit`: 生产单位
  - `conversion_factor`: 单位转换系数

#### 1.3 增强生产订单模型
- **文件**: `backend/common/models/pp.py`
- **模型**: `ProductionOrder`
- **新增字段**:
  - `sales_quantity`: 关联的销售订单数量
  - `sales_unit`: 关联的销售订单单位
  - `conversion_factor`: 单位转换系数

## 业务流程改进

### 1. 报价单转销售订单流程
```
报价单 (product_number: 本厂编号)
    ↓
自动查找 FactoryProductMapping
    ↓
获取 material_code 和 production_version_id
    ↓
从 Material 获取单位转换信息
    ↓
计算 production_quantity 和 production_unit
    ↓
创建销售订单（自动填充所有字段）
```

### 2. 销售订单转生产订单流程
```
销售订单 (material_code, production_version_id, production_quantity, production_unit)
    ↓
验证生产版本状态（RELEASED 或 ACTIVE）
    ↓
验证物料编码一致性
    ↓
从销售订单获取单位转换信息
    ↓
创建生产订单（自动填充单位转换信息）
```

## 数据验证规则

1. **销售订单创建时**:
   - 验证物料存在且状态为 ACTIVE
   - 验证生产版本状态为 RELEASED 或 ACTIVE
   - 验证生产版本的物料编码与映射一致

2. **生产订单创建时**:
   - 验证销售订单状态为 APPROVED
   - 验证生产版本状态为 RELEASED 或 ACTIVE
   - 验证物料编码与生产版本一致

3. **本厂编号映射创建时**:
   - 验证客户存在
   - 验证物料存在
   - 验证生产版本存在（如果提供）
   - 验证生产版本的物料编码与映射一致

## 单位转换逻辑

1. **销售订单**:
   - `sales_unit`: 从物料的 `base_unit` 获取（默认：PCS）
   - `production_unit`: 从物料的 `production_unit` 获取（默认：PNL）
   - `conversion_factor`: 从物料的 `conversion_factor` 获取（默认：1.0）
   - `production_quantity`: 根据单位转换计算（如果单位不同）

2. **生产订单**:
   - 从销售订单继承单位转换信息
   - `sales_quantity`: 销售订单的销售数量
   - `sales_unit`: 销售订单的销售单位
   - `conversion_factor`: 销售订单的转换系数
