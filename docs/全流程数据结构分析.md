# 客户建档-报价单-销售订单-工单全流程数据结构分析

## 一、当前数据流分析

### 1.1 数据流程链路

```
客户建档 (Customer)
    ↓
报价单 (Quotation) - 使用 product_number (本厂编号，如HS1004ENIGAB01)
    ↓
销售订单 (SalesOrder) - 继承 product_number
    ↓
生产订单 (ProductionOrder) - 使用 material_code + production_version_id
    ↓
工序报工 (OperationReport)
```

### 1.2 关键数据模型关联

#### 客户主数据 (Customer)
- ✅ 结构完整：基本信息、地址、联系人、合作属性、销售数据
- ✅ 状态管理：DRAFT → PENDING_APPROVAL → ACTIVE/BLOCKED/INACTIVE

#### 报价单 (Quotation)
- ⚠️ **问题1**: 使用 `product_number`（本厂编号），未关联到系统 `material_code`
- ⚠️ **问题2**: 缺少物料主数据关联，无法自动获取物料属性
- ✅ 状态流转：DRAFT → 审核流程 → APPROVED → CUSTOMER_CONFIRMED → LINKED

#### 销售订单 (SalesOrder)
- ⚠️ **问题3**: 继承 `product_number`，但创建生产订单时需要 `material_code`
- ⚠️ **问题4**: 缺少从 `product_number` 到 `material_code` 的映射机制
- ✅ 状态流转：DRAFT → 评审 → APPROVED → IN_PRODUCTION → COMPLETED → SHIPPED → DELIVERED → RECONCILED → CLOSED

#### 生产订单 (ProductionOrder)
- ✅ 使用 `production_version_id`（包含BOM+Routing+MI）
- ✅ 关联 `material_code` 和 `sales_order_number`
- ⚠️ **问题5**: `material_code` 需要从销售订单的 `product_number` 转换而来，但缺少转换逻辑

#### 工程数据
- ✅ BOM：物料清单，关联到物料
- ✅ Routing：工艺路线，关联到物料和工作中心
- ✅ ProductionVersion：生产版本（BOM+Routing+MI组合）
- ✅ WorkCenter：工作中心，支持层级和PCB行业属性

## 二、发现的问题

### 2.1 本厂编号与物料编码的映射缺失

**问题描述**：
- 报价单和销售订单使用 `product_number`（本厂编号，如HS1004ENIGAB01）
- 生产订单使用 `material_code`（系统物料编码）
- **缺少两者之间的映射关系**

**影响**：
1. 从销售订单创建生产订单时，无法自动确定 `material_code`
2. 需要人工选择物料，容易出错
3. 无法自动验证产品规格是否匹配

**建议解决方案**：
```python
# 方案1：在Material表中添加factory_product_number字段
class Material(BaseModel):
    material_code = Column(String(50), unique=True, nullable=False)
    factory_product_number = Column(String(50))  # 本厂编号
    # 一个物料可以有多个本厂编号（一对多关系）

# 方案2：创建独立的映射表（推荐）
class FactoryProductMapping(BaseModel):
    """本厂编号映射表"""
    __tablename__ = "factory_product_mappings"
    
    customer_id = Column(String(50), ForeignKey("customers.customer_id"), nullable=False)
    factory_product_number = Column(String(50), nullable=False)  # 本厂编号
    material_code = Column(String(50), ForeignKey("materials.material_code"), nullable=False)
    is_default = Column(Boolean, default=True)  # 是否为默认映射
    effective_date = Column(DateTime, nullable=False)
    expiry_date = Column(DateTime)
    
    # 唯一约束：同一客户的本厂编号在同一时间段内唯一
    __table_args__ = (
        UniqueConstraint('customer_id', 'factory_product_number', 'effective_date'),
    )
```

### 2.2 销售订单缺少生产版本信息

**问题描述**：
- 销售订单只有 `product_number`，没有 `production_version_id`
- 创建生产订单时，需要手动选择生产版本
- 无法在销售阶段就确定生产版本

**影响**：
1. 无法在销售订单阶段验证生产版本是否存在
2. 无法提前进行产能评估
3. 创建生产订单时可能发现生产版本不存在

**建议解决方案**：
```python
class SalesOrder(BaseModel):
    # ... 现有字段 ...
    material_code = Column(String(50), ForeignKey("materials.material_code"))  # 添加物料编码
    production_version_id = Column(String(50), ForeignKey("production_versions.production_version_id"))  # 添加生产版本
    # 如果production_version_id为空，创建生产订单时再选择
```

### 2.3 报价单缺少物料明细关联

**问题描述**：
- 报价单有 `QuotationItem`，但 `material_code` 是可选的
- 报价单明细主要用于价格展示，未关联到BOM

**影响**：
1. 无法从报价单直接生成BOM需求
2. 无法进行成本核算
3. 报价单和BOM数据割裂

**建议**：
- 保持现状（报价单主要用于商务，BOM用于生产）
- 但建议在报价单明细中，如果可能，关联 `material_code`

### 2.4 生产订单数量单位转换

**问题描述**：
- 销售订单数量单位可能是 `PCS`（个）
- 生产订单数量单位可能是 `PNL`（拼板）
- 需要单位转换：1 PNL = 6 PCS（举例）

**当前处理**：
- ProductionOrder 有 `quantity` 和 `unit` 字段
- 但缺少与销售订单数量的自动转换逻辑

**建议解决方案**：
```python
class ProductionOrder(BaseModel):
    # ... 现有字段 ...
    sales_order_quantity = Column(Numeric(15, 2))  # 销售订单数量
    sales_order_unit = Column(String(20))  # 销售订单单位
    production_quantity = Column(Numeric(15, 2))  # 生产数量（可能不同单位）
    production_unit = Column(String(20))  # 生产单位
    conversion_factor = Column(Numeric(15, 4))  # 转换系数
```

### 2.5 物料主数据与报价单产品信息不一致

**问题描述**：
- 报价单有 `layers`（层数）、`product_series`（产品系列）等字段
- 物料主数据也有 `layer_count` 等字段
- 两者可能不一致

**建议**：
- 报价单阶段，产品可能还未在系统中创建物料
- 建议在报价单转销售订单时，自动创建或匹配物料
- 或者要求报价前必须先有物料主数据

### 2.6 生产版本状态管理

**问题描述**：
- ProductionVersion 有 `status` 字段（ACTIVE/RELEASED等）
- 但销售订单创建时，可能未验证生产版本状态
- 可能导致选择已废弃的生产版本

**建议**：
- 在创建生产订单时，验证 `production_version.status` 必须是 `RELEASED` 或 `ACTIVE`
- 在销售订单中关联生产版本时，也要验证状态

### 2.7 工作中心与工艺路线的关联

**当前状态**：
- ✅ RoutingOperation 关联 WorkCenter
- ✅ OperationReport 关联 WorkCenter
- ✅ 结构合理

**建议**：
- 在创建生产订单时，可以提前验证工作中心是否可用（状态为ACTIVE）

## 三、改进建议

### 3.1 数据模型改进（高优先级）

#### 1. 添加本厂编号映射表
```python
class FactoryProductMapping(BaseModel):
    """本厂编号映射表"""
    __tablename__ = "factory_product_mappings"
    
    id = Column(Integer, primary_key=True)
    customer_id = Column(String(50), ForeignKey("customers.customer_id"), nullable=False)
    factory_product_number = Column(String(50), nullable=False)
    material_code = Column(String(50), ForeignKey("materials.material_code"), nullable=False)
    production_version_id = Column(String(50), ForeignKey("production_versions.production_version_id"))
    is_default = Column(Boolean, default=True)
    effective_date = Column(DateTime, nullable=False)
    expiry_date = Column(DateTime)
    created_by = Column(String(50))
    created_at = Column(DateTime)
    
    # 关联
    customer = relationship("Customer")
    material = relationship("Material")
    production_version = relationship("ProductionVersion")
    
    __table_args__ = (
        UniqueConstraint('customer_id', 'factory_product_number', 'effective_date', name='uq_factory_product'),
    )
```

#### 2. 增强销售订单模型
```python
class SalesOrder(BaseModel):
    # ... 现有字段 ...
    
    # 添加字段
    material_code = Column(String(50), ForeignKey("materials.material_code"))
    production_version_id = Column(String(50), ForeignKey("production_versions.production_version_id"))
    sales_quantity = Column(Numeric(15, 2))  # 销售数量（原quantity重命名）
    sales_unit = Column(String(20))  # 销售单位（新增）
    production_quantity = Column(Numeric(15, 2))  # 生产数量（新增）
    production_unit = Column(String(20))  # 生产单位（新增）
```

#### 3. 增强生产订单模型
```python
class ProductionOrder(BaseModel):
    # ... 现有字段 ...
    
    # 添加字段
    sales_quantity = Column(Numeric(15, 2))  # 关联的销售订单数量
    sales_unit = Column(String(20))  # 关联的销售订单单位
    conversion_factor = Column(Numeric(15, 4))  # 单位转换系数
```

### 3.2 业务流程改进

#### 1. 报价单转销售订单流程
```
报价单 (product_number)
    ↓
查找 FactoryProductMapping
    ↓
获取 material_code 和 production_version_id
    ↓
创建销售订单（自动填充 material_code 和 production_version_id）
    ↓
验证生产版本状态（必须是 RELEASED 或 ACTIVE）
```

#### 2. 销售订单转生产订单流程
```
销售订单 (material_code, production_version_id, quantity, unit)
    ↓
验证生产版本状态
    ↓
获取 ProductionVersion (包含 BOM + Routing + MI)
    ↓
计算生产数量（考虑单位转换）
    ↓
创建生产订单
```

#### 3. 物料创建时机
- **方案A（推荐）**：报价前必须先创建物料主数据
  - 优点：数据一致性高，可以自动关联
  - 缺点：报价流程变复杂
  
- **方案B**：报价时允许临时本厂编号，转销售订单时再创建物料
  - 优点：报价流程灵活
  - 缺点：需要额外的物料创建步骤

### 3.3 数据一致性改进

#### 1. 添加数据验证规则
- 销售订单创建时，验证 `material_code` 存在且状态为 ACTIVE
- 生产订单创建时，验证 `production_version_id` 状态为 RELEASED 或 ACTIVE
- 生产订单创建时，验证 `material_code` 与 `production_version.material_code` 一致

#### 2. 添加数据同步机制
- 销售订单状态变更时，同步更新关联的生产订单状态
- 生产订单完成时，同步更新销售订单状态（已实现）

### 3.4 查询性能优化

#### 1. 添加索引
```sql
-- 本厂编号映射表
CREATE INDEX idx_factory_product_mapping ON factory_product_mappings(customer_id, factory_product_number);

-- 销售订单
CREATE INDEX idx_sales_order_material ON sales_orders(material_code);
CREATE INDEX idx_sales_order_production_version ON sales_orders(production_version_id);

-- 生产订单
CREATE INDEX idx_production_order_sales ON production_orders(sales_order_number);
CREATE INDEX idx_production_order_material ON production_orders(material_code);
CREATE INDEX idx_production_order_version ON production_orders(production_version_id);
```

## 四、实施优先级

2. ✅ **增强销售订单模型** - 添加 material_code 和 production_version_id
3. ✅ **添加数据验证逻辑** - 确保数据一致性

### 中优先级（建议实施）

5. ⚠️ **生产版本状态验证** - 在创建生产订单时验证状态
6. ⚠️ **物料创建时机优化** - 明确物料创建的最佳时机

### 低优先级（可选）
7. ⚠️ **报价单明细关联物料** - 如果业务需要，可以关联
8. ⚠️ **工作中心可用性验证** - 提前验证工作中心状态

## 五、总结

### 当前架构优点
1. ✅ 模块划分清晰（SD/PP/ENG/MM）
2. ✅ 生产版本设计合理（BOM+Routing+MI组合）
3. ✅ 工作中心支持PCB行业特性
4. ✅ 状态流转逻辑清晰

### 主要问题
1. ❌ **本厂编号与物料编码映射缺失** - 最关键的问题
2. ❌ **销售订单缺少生产版本信息** - 影响生产订单创建
3. ❌ **单位转换机制不完善** - 可能导致数量错误

### 改进方向
1. 建立本厂编号到物料编码的映射机制
2. 在销售订单阶段就确定生产版本
3. 完善单位转换和数量计算逻辑
4. 加强数据验证和一致性检查
