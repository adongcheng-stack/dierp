## 六、详细差异分析

### 6.1 产品主数据管理实现方式

**需求文档描述：**
- 产品主数据是ENG模块的核心功能
- 以本厂编号作为唯一标识
- 包含物料主数据中成品(FG)的所有内容

**代码实现方式：**
- 产品主数据通过`Material`实体实现（`material_type='FG'`）
- ENG模块提供产品主数据映射API（`/api/eng/product-mappings`）
- 映射功能：本厂编号 ↔ 物料编码/生产版本ID

**差异分析：**
- 功能上：产品主数据管理功能已实现，但实现方式与需求文档描述不完全一致
- 接口上：缺少独立的产品主数据CRUD API，需要通过Material API + Mapping API组合
- 影响：前端需要调用两个API才能完成产品主数据管理

**建议：**
1. **方案1（推荐）**：在ENG模块添加独立的产品主数据CRUD API
   - `POST /api/eng/products` - 创建产品主数据
   - `GET /api/eng/products` - 查询产品主数据列表
   - `GET /api/eng/products/{product_number}` - 查询产品主数据详情
   - `PUT /api/eng/products/{product_number}` - 更新产品主数据
   - 内部调用Material API创建/更新FG类型物料

2. **方案2**：在需求文档中明确说明产品主数据管理通过Material API + FactoryProductMapping API实现

### 6.2 工作中心激活/停用功能

**需求文档描述：**
- 工作中心激活：激活工作中心，使其可用于生产

### 6.3 不良品管理功能

**需求文档描述：**
- 不良品管理：记录不良品信息，包含不良原因、处理方式、责任工序等
- 支持记录多个不良品记录，每个记录包含：不良类型、数量、处理方式、责任工序、备注

**代码实现方式：**
- OperationReport实体有`scrap_quantity`字段（报废数量）
- OperationReport实体有`good_quantity`字段（良品数量）
- 缺少详细的不良品信息字段

**差异分析：**
- 功能上：仅实现报废数量记录，缺少详细不良品信息
- 数据结构：缺少不良原因、处理方式、责任工序等字段
- 影响：无法记录详细的不良品信息，无法进行不良品分析

**建议：**
1. **方案1（推荐）**：扩展OperationReport实体
   - 添加`defect_records`字段（JSON格式），存储多个不良品记录

2. **方案2**：创建独立的DefectRecord实体
   - 关联到OperationReport

3. **方案3**：在需求文档中说明当前仅支持记录报废数量，详细不良品管理为后续功能
