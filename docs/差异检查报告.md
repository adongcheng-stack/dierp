## 八、详细差异分析

### 8.1 生产订单 / 工单一体化建模分析

**需求文档中的概念：**
- 实体名称：工单
- 说明：生产工单，由生产订单生成，包含工序任务、工作中心、计划时间等
- ER图中：存在workOrder实体，与productionOrder关联

**代码实现中的选择：**
- 使用 `ProductionOrder` 作为唯一的生产执行主实体：
  - 既承接销售订单（订单层）
  - 又承载工序执行与报工（执行层）的聚合根职能
- 工序级别的信息通过：
  - `RoutingOperation` 定义标准工艺步骤
  - `OperationReport` 记录实际执行与报工
  - `ProductionProgress` 用于看板统计

**结论：**
- 功能视角：✅ 工单相关功能（下达、执行、报工、进度）已由ProductionOrder + RoutingOperation + OperationReport + ProductionProgress 共同覆盖
- 建模视角：✨ 采用“生产订单/工单合一”的简化模型，降低MVP复杂度
- 文档需在相关处明确：**“生产订单在实现中同时承担工单职责，当前版本不单独建WorkOrder表”**
