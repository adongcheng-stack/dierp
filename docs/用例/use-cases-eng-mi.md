## 详细用例描述

### UC-ENG-009: 创建MI

**用例编号**：UC-ENG-009  
**用例名称**：创建MI  
**用例参与者**：工程师（主要）  
**用例概述**：工程师创建制造指令（MI），包含客户型号、技术参数等。MI可以基于工艺路线自动生成草稿，工程师可以添加MI指令集列表和描述，调整指令集顺序。MI内容以JSON格式存储。  
**触发条件**：工程师需要为产品创建MI，点击"创建MI"按钮或菜单项。  
**前置条件**：
- 用户已登录系统
- 用户具有ENGINEER角色
- 物料已存在

**基本流程**：
1. 工程师选择"创建MI"
2. 系统显示MI创建表单
3. 工程师选择物料（必填）
4. 系统验证物料存在
5. 工程师可以选择工艺路线（可选）
6. 如果选择了工艺路线：
   - 6a. 系统基于工艺路线自动生成MI草稿
   - 6b. 系统自动填充指令集列表
7. 工程师填写MI基本信息：
   - MI编号（必填，系统自动生成或手动输入）
   - 版本号（必填）
   - 生效日期（必填）
   - 失效日期（可选）
8. 工程师添加MI指令集：
   - 指令序号（必填）
   - 指令名称（必填）
   - 指令描述（可选）
9. 工程师可以添加多个指令集
10. 工程师可以调整指令集顺序（使用上下箭头）
11. 工程师点击"保存"
12. 系统验证必填字段
13. 系统将指令集列表和描述以JSON格式存储到content字段
14. 系统创建MI记录，状态为DRAFT
15. 系统显示"MI创建成功"消息

**扩展流程**：
- 4a. 物料不存在
  - 4a.1 系统显示"物料不存在"错误消息
  - 4a.2 返回步骤3
- 12a. 必填字段验证失败
  - 12a.1 系统显示验证错误消息
  - 12a.2 返回步骤7

**后置条件**：
- MI记录已创建，状态为DRAFT
- MI内容以JSON格式存储
- MI可以提交审批

**特殊需求**：
- BR-ENG-017: MI可以基于工艺路线自动生成草稿
- BR-ENG-018: MI必须经过审批流程：DRAFT → REVIEWING → APPROVED → RELEASED
- BR-ENG-346: MI内容以JSON格式存储，包含指令集列表和描述

### UC-ENG-010: 基于工艺路线生成MI草稿

**用例编号**：UC-ENG-010  
**用例名称**：基于工艺路线生成MI草稿  
**用例参与者**：工程师（主要）  
**用例概述**：工程师选择已发布的工艺路线，系统自动生成MI草稿（指令集初始列表），工程师可在此基础上编辑完善。  
**触发条件**：工程师在MI创建界面选择"基于工艺路线生成草稿"。  
**前置条件**：
- 用户已登录系统
- 用户具有ENGINEER角色
- 目标工艺路线状态为RELEASED

**基本流程**：
1. 工程师选择工艺路线
2. 系统校验工艺路线状态为RELEASED
3. 系统基于工艺路线生成MI草稿，预填指令集
4. 系统创建MI草稿记录，状态为DRAFT
5. 工程师可继续编辑后保存

**扩展流程**：
- 2a. 工艺路线状态不为RELEASED
  - 2a.1 系统提示"工艺路线未发布，无法生成MI草稿"
  - 2a.2 用例结束

**后置条件**：
- 生成一个MI草稿记录，关联所选工艺路线

**特殊需求**：
- 生成的指令集可编辑；发布前必须经过审批

### UC-ENG-011: 更新MI

**用例编号**：UC-ENG-011  
**用例名称**：更新MI  
**用例参与者**：工程师（主要）  
**用例概述**：工程师在MI处于DRAFT或REVIEWING状态下更新MI内容（指令集、参数等），用于修正制造指令。  
**触发条件**：工程师在MI详情页点击"编辑"。  
**前置条件**：
- 用户已登录系统
- 用户具有ENGINEER角色
- MI状态为DRAFT或REVIEWING

**基本流程**：
1. 工程师点击"编辑MI"
2. 系统显示当前MI内容（JSON）
3. 工程师编辑指令集、参数等
4. 系统校验必填项与格式
5. 工程师点击"保存"
6. 系统更新MI记录

**扩展流程**：
- 4a. JSON格式或必填校验失败
  - 4a.1 系统提示错误并返回编辑

**后置条件**：
- MI记录已更新

**特殊需求**：
- RELEASED状态需走变更流程而非直接修改

### UC-ENG-012: 审批MI

**用例编号**：UC-ENG-012  
**用例名称**：审批MI  
**用例参与者**：工程师/审核员（主要）  
**用例概述**：审批人对MI进行审核，审核通过后MI状态从REVIEWING变为APPROVED；审核拒绝退回DRAFT并记录原因。  
**触发条件**：审核员在待审MI列表点击"审批"或"拒绝"。  
**前置条件**：
- 用户已登录系统
- 用户具有MI审核权限
- MI状态为REVIEWING

**基本流程**：
1. 审核员打开待审MI
2. 审核员查看内容并填写意见（可选）
3. 审核员点击"通过"
4. 系统将MI状态更新为APPROVED
5. 系统记录审批历史

**扩展流程**：
- 3a. 选择"拒绝"
  - 3a.1 系统要求填写拒绝原因（必填）
  - 3a.2 系统将MI状态更新为DRAFT
  - 3a.3 系统记录审批历史

**后置条件**：
- 审批通过：MI状态为APPROVED
- 审批拒绝：MI状态为DRAFT

**特殊需求**：
- 审批/拒绝需记录审批人、时间、意见/原因

---

### UC-ENG-013: 发布MI

**用例编号**：UC-ENG-013  
**用例名称**：发布MI  
**用例参与者**：工程师（主要）  
**用例概述**：工程师将已审批通过的MI发布为RELEASED，发布后可用于生产订单/工单和LOT卡生成。  
**触发条件**：工程师在MI详情点击"发布"。  
**前置条件**：
- 用户已登录系统
- 用户具有ENGINEER角色
- MI状态为APPROVED

**基本流程**：
1. 工程师点击"发布"
2. 系统校验MI状态为APPROVED
3. 系统更新MI状态为RELEASED
4. 系统记录发布时间和发布人
5. 系统提示"MI已发布"

**扩展流程**：
- 2a. 状态校验不通过
  - 2a.1 系统提示错误并结束

**后置条件**：
- MI状态为RELEASED，可用于生产版本发布和生产订单

**特殊需求**：
- RELEASED后的修改需走变更/新版本流程
