- **用例参与者**：参与用例的主要和次要参与者
- **用例概述**：用例的功能概述和业务价值
- **触发条件**：启动用例的条件或事件
- **前置条件**：用例执行前必须满足的条件
- **基本流程**：用例的主要执行步骤
- **扩展流程**：用例的异常处理和备选路径
- **后置条件**：用例执行后系统的状态
- **特殊需求**：用例的特殊业务规则、约束条件或非功能性需求

## 详细用例描述

### UC-ENG-002: 创建物料

**用例编号**：UC-ENG-002  
**用例名称**：创建物料  
**用例参与者**：工程师（主要）  
**用例概述**：工程师创建非成品类物料（原材料、半成品等），录入物料编码、名称、类型、单位、库存参数等信息，为BOM和库存管理提供基础数据。  
**触发条件**：工程师在物料管理中点击"创建物料"。  
**前置条件**：
- 用户已登录系统
- 用户具有ENGINEER角色

**基本流程**：
1. 工程师点击"创建物料"
2. 系统显示物料创建表单
3. 工程师填写物料编码（唯一）、名称、物料类型、单位等必填信息
4. 系统校验物料编码唯一性
5. 工程师点击"保存"
6. 系统创建物料记录，状态为ACTIVE

**扩展流程**：
- 4a. 物料编码已存在
  - 4a.1 系统提示"物料编码已存在"
  - 4a.2 返回步骤3

**后置条件**：
- 物料记录已创建，可用于BOM、生产领料等

**特殊需求**：
- 物料编码必须唯一
- 成品(FG)物料通过产品主数据管理，不在此用例创建

### UC-ENG-002A: 更新物料

**用例编号**：UC-ENG-002A  
**用例名称**：更新物料  
**用例参与者**：工程师（主要）  
**用例概述**：工程师更新物料主数据，如名称、单位、参数等，不允许修改物料编码。  
**触发条件**：工程师在物料详情中点击"编辑"。  
**前置条件**：
- 用户已登录系统
- 用户具有ENGINEER角色
- 物料已存在

**基本流程**：
1. 工程师选择物料并点击"编辑"
2. 系统显示物料信息
3. 工程师修改允许变更的字段（物料编码不可改）
4. 工程师点击"保存"
5. 系统更新物料记录

**扩展流程**：
- 3a. 修改字段不合法
  - 3a.1 系统提示错误，返回编辑

**后置条件**：
- 物料主数据已更新

**特殊需求**：
- 物料编码不可修改
- 成品(FG)物料更新需通过产品主数据管理

### UC-ENG-003: 创建BOM

**用例编号**：UC-ENG-003  
**用例名称**：创建BOM  
**用例参与者**：工程师（主要）  
**用例概述**：工程师创建物料清单（BOM），定义产品的物料组成结构。父项为产品主数据（产品编码为本厂编号），包含多个BOM明细项，每个明细项定义子物料、数量、单位等信息。  
**触发条件**：工程师需要为产品创建BOM，点击"创建BOM"按钮或菜单项。  
**前置条件**：
- 用户已登录系统
- 用户具有ENGINEER角色
- 父项产品主数据已存在（如果不存在，系统提示用户创建）

**基本流程**：
1. 工程师选择"创建BOM"
2. 系统显示BOM创建表单
3. 工程师选择父项产品（必填，通过本厂编号选择）
4. 系统验证产品主数据存在（如果本厂编号对应的产品主数据不存在，系统提示用户创建）
5. 工程师填写BOM基本信息：
   - BOM编号（必填，系统自动生成或手动输入）
   - 版本号（必填）
   - 基数（默认1）
   - 基础单位（默认PNL）
   - 生效日期（必填）
   - 失效日期（可选）
6. 工程师添加BOM明细：
   - 行号（必填）
   - 子物料（必填）
   - 物料类别（STOCK_ITEM/SUB_ASSEMBLY/CONSUMABLE）
   - 数量（必填）
   - 单位（必填）
   - 损耗率（可选）
   - 层码（PCB专用，可选）
   - 物料类型（PCB专用，可选）
7. 工程师可以添加多个BOM明细
8. 工程师点击"保存"
9. 系统验证必填字段
10. 系统验证子物料存在
11. 系统创建BOM记录，状态为NEW
12. 系统创建BOM明细记录
13. 系统显示"BOM创建成功"消息

**扩展流程**：
- 4a. 父物料不存在
  - 4a.1 系统显示"父物料不存在"错误消息
  - 4a.2 返回步骤3
- 9a. 必填字段验证失败
  - 9a.1 系统显示验证错误消息
  - 9a.2 返回步骤5
- 10a. 子物料不存在
  - 10a.1 系统显示"子物料不存在"错误消息
  - 10a.2 返回步骤6

**后置条件**：
- BOM记录已创建，状态为NEW
- BOM明细记录已创建
- BOM可以提交审批

**特殊需求**：
- BR-ENG-005: BOM必须经过审批流程：NEW → REVIEWING → RELEASED
- BR-ENG-008: BOM的base_uom通常为PNL（拼板），用于PCB行业

### UC-ENG-004: 更新BOM

**用例编号**：UC-ENG-004  
**用例名称**：更新BOM  
**用例参与者**：工程师（主要）  
**用例概述**：工程师在BOM处于NEW或REVIEWING状态时更新BOM基础信息或明细（子物料、数量、单位等），用于修正设计。  
**触发条件**：工程师在BOM详情页点击"编辑"。  
**前置条件**：
- 用户已登录系统
- 用户具有ENGINEER角色
- BOM状态为NEW或REVIEWING

**基本流程**：
1. 工程师点击"编辑BOM"
2. 系统显示BOM基本信息和明细
3. 工程师修改允许变更的字段/明细
4. 系统校验必填字段和明细合法性
5. 工程师点击"保存"
6. 系统更新BOM记录

**扩展流程**：
- 4a. 明细为空或必填校验失败
  - 4a.1 系统提示错误并返回编辑

**后置条件**：
- BOM记录已更新

**特殊需求**：
- RELEASED状态的BOM需要创建新版本而非直接修改

---

### UC-ENG-005: 发布BOM

**用例编号**：UC-ENG-005  
**用例名称**：发布BOM  
**用例参与者**：工程师（主要）  
**用例概述**：工程师发布BOM，将BOM状态从REVIEWING更新为RELEASED。只有RELEASED状态的BOM才能用于生产版本。  
**触发条件**：BOM状态为REVIEWING，工程师需要发布BOM，点击"发布"按钮。  
**前置条件**：
- 用户已登录系统
- 用户具有ENGINEER角色
- BOM状态为REVIEWING

**基本流程**：
1. 工程师选择BOM
2. 工程师点击"发布"
3. 系统验证BOM状态为REVIEWING
4. 系统验证BOM必填字段完整
5. 系统验证BOM明细不为空
6. 系统将BOM状态更新为RELEASED
7. 系统显示"BOM已发布"消息

**扩展流程**：
- 3a. BOM状态不是REVIEWING
  - 3a.1 系统显示"BOM状态无效，无法发布"错误消息
  - 3a.2 用例结束
- 4a. 必填字段不完整
  - 4a.1 系统显示"请填写所有必填字段"错误消息
  - 4a.2 用例结束
- 5a. BOM明细为空
  - 5a.1 系统显示"BOM明细不能为空"错误消息
  - 5a.2 用例结束

**后置条件**：
- BOM状态为RELEASED
- BOM可以用于生产版本

**特殊需求**：
- BR-ENG-006: 只有RELEASED状态的BOM才能用于生产版本
