## P0：N2 权限门把匿名 GET 也变成 401（已修）

### 现象

修复前实测：

```
401  GET /api/sd/customers
401  GET /api/pp/production-orders
401  GET /api/mm/materials
401  GET /api/planning/planned-orders
401  GET /api/qms/inspections
401  GET /api/purchase/purchase-orders
200  GET /api/traceability/overview     ← 没挂权限门，所以正常
200  GET /api/dashboard/management      ← 同上
```

### 根因

`require_write_permission` 把 `current_user: User = Depends(get_current_user)` 写成了参数。FastAPI 的依赖解析**先于**函数体执行，而 `get_current_user` 依赖的 `OAuth2PasswordBearer` 默认 `auto_error=True` —— 于是任何请求（含 GET）在进入 `if request.method not in WRITE_METHODS` 之前就已被 401 拦截。文档里写的「GET 不受限」与实现相反。

同一个根因还导致 **CORS 预检 OPTIONS 被 401**，浏览器端写操作会直接失败。

### 影响

1. 基线（`49c5c25`）的只读 API 是匿名可访问的，N2 之后全部需要 token —— 对外契约破坏，任何未登录的只读调用（对接脚本、curl 验证、登录页预取）都会失败。
2. 前端 30 分钟 token 过期后，**任意一次只读刷新都会跳登录**（`api.ts` 的 401 处理是 logout + 跳转），演示中途会突然被踢出。
3. `test_get_remains_open_for_smoke_scripts` 只断言了 traceability/dashboard 两个**没有挂权限门**的路由，所以测试全绿但回归漏网。

### 修复

- `auth.py` 抽出 `_resolve_user_from_token()`，新增 `oauth2_scheme_optional`（`auto_error=False`）；`require_write_permission` 改为自行取可选 token，**只在写方法上**判定 401/403。
- `test_permissions.py` 的只读断言扩展到 9 个域；新增 CORS 预检用例。

### 修复后实测

```
200  GET /api/sd/customers …（9 个域全部 200）
401  GET /api/users                      ← 用户管理本就需要登录，保持
401  匿名 POST /api/sd/customers
403  PLANNER POST /api/sd/customers
200  OPTIONS /api/sd/customers（预检，带 allow-origin）
```

## P1

### P1-1 Alembic 会主动生成「删除真实索引」的脚本（已修）

`env.py` 的 `include_object` 原实现对非 table 对象一律 `return True`，`alembic check` 因此提议：

```
Detected removed index 'idx_sales_order_production_version' on 'sales_orders'
```

这些索引由 MVP 手写 SQL 创建，不在模型元数据里。一旦有人直接 `revision --autogenerate && upgrade head`，会**删掉线上真实索引**（含唯一索引）。

修复：`reflected and compare_to is None` 的子对象（索引/约束/列）一律忽略，仅比对元数据登记表上的对象。修复后 `drop_index` 提议消失。

### P1-2 Alembic 基线并不干净，`check` 仍为红（未修，建议独立任务）

修完索引后仍报大量漂移，说明**模型与实库长期不一致**：

- `factory_product_mappings` 三个列库里 nullable、模型 not null；
- 模型声明的 `ix_*` 索引在库里不存在（如 `ix_lot_cards_lot_number`）；
- `lot_cards` / `mi_instructions` 的列注释、表注释、外键库里缺失。

因此 N4 的 Alembic 目前只能当「人工审查辅助」，**不能进 CI 门禁，也不能证明零漂移**。要真正可用需要一次「对齐迁移」（补索引/FK 或把模型放宽到实库），建议单独立项，不要在演示前动结构。

### P1-3 mock 完全没有 RBAC，与「同构」原则冲突（未修）

`handlers.ts` 中 `403` 出现次数为 0，`WRITE_ROLE_POLICY` 不存在。后果：mock 演示（4173）里任何角色都能写任何域，N2 的权限设计在演示中不可见，且与真实后端行为分叉。

建议：mock 加一个轻量 `WRITE_ROLE_POLICY` 映射（同一份角色表），在 `route()` 写方法入口判定 403。工作量小，收益是演示与真机一致。

### P1-4 测试套件是「混合隔离」（未修，建议）

`conftest.py` 提供 SQLite 内存库夹具，但 `test_permissions.py` 没有请求 `db` 夹具，走的是 `TestClient(app)` + 真实 PostgreSQL：

- 同一套 pytest 里，一半测试用内存库、一半打真实库；
- 无 PG 的环境（CI/新机器）跑 `pytest` 会直接失败；
- 权限测试会读取真实用户表，依赖演示数据存在。

建议：用 `app.dependency_overrides[get_db]` 把权限测试也接到 SQLite，并插入三个最小用户（ADMIN/PLANNER/SALES）。届时 `pytest` 才真正不依赖外部服务。
