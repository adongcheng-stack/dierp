# DIERP 下一阶段实施计划
## Phase 2：APS 有限产能排程 + 甘特图 + 插单模拟

| 项目 | 内容 |
|---|---|
| 文档版本 | v0.1 |
| 适用阶段 | Phase 1（MRP/MPS 计划闭环）完成之后 |
| 建议周期 | 4–5 周 |
| 核心目标 | 把 MRP 下达的生产订单转化为“可执行、可调整、可模拟”的工序级作业计划 |
| 技术目标 | 建立有限产能排程引擎、甘特图交互视图、插单模拟与约束校验能力 |
| 前置条件 | Phase 1 的计划订单确认/下达、齐套分析、service 层抽象已稳定 |
| 本阶段不做 | 工业级优化算法、完整 QMS、EAM、成本核算、SRM/WMS、多工厂多组织 |

## 1. 阶段目标与边界

### 1.1 本阶段要解决的问题

Phase 1 解决了“需要生产什么、需要多少、什么时候需要”，但生产订单下达后仍依赖人工排序。实际制造现场存在：

- 设备产能有限，不能假设无限产能；
- 班次、工作日历、设备停机影响可用工时；
- 人员技能矩阵不匹配；
- 换产/换模需要准备时间；
- 物料不齐套，排了也做不了；
- 插单、设备故障、物料延期导致计划频繁变化；
- 需要直观看到工序级甘特图，并支持拖拽调整。

Phase 2 要回答：

- 每道工序在哪台设备、哪个班次、什么时间做？
- 设备/人员/物料约束下，交期能否满足？
- 插单后哪些订单受影响、影响多少？
- 拖拽调整后是否违反约束？
- 缺料或设备故障后如何快速重排？

### 1.2 本阶段交付结果

1. 有限产能排程引擎：支持正排、倒排、混合排程；
2. 约束建模：工作日历、班次、设备产能、人员技能、换产矩阵、物料齐套；
3. 工序级甘特图：按工作中心/设备/订单查看，支持拖拽调整与约束校验；
4. 插单模拟：模拟新订单插入、设备故障、物料延期对交期的影响；
5. 排程异常清单：设备冲突、人员冲突、缺料、交期延误、换产超限；
6. 排程结果可发布为作业计划，并回写生产订单工序计划；
7. 演示数据覆盖设备冲突、换产、缺料、插单四类场景。

### 1.3 本阶段不做

- 高级智能优化算法（遗传算法、约束规划求解器）；
- 多工厂、多组织、跨基地协同排程；
- 模具/工装全生命周期管理；
- 高级人工排班与考勤；
- 完整 MES 数据采集与设备联网；
- 成本最优排程；
- 完整 QMS/EAM/成本/业财功能。

## 5. 排程逻辑

### 5.1 排程输入

- Phase 1 下达的生产订单及工序；
- 工艺路线与标准工时；
- 工作中心、设备、人员、班次、日历；
- 换产矩阵；
- 物料齐套结果；
- 生产订单优先级与交期；
- 排程参数。

### 5.2 排程策略

| 策略 | 说明 | 适用场景 |
|---|---|---|
| 正排 | 从最早可开始时间向后排 | 物料充足、尽快生产 |
| 倒排 | 从交期向前倒推 | 交期驱动、JIT |
| 混合排程 | 关键工序倒排，其余正排 | 兼顾交期与产能 |
| 优先级排程 | 按订单优先级/交期排序 | 插单频繁场景 |

### 5.3 计算步骤

```text
1. 读取待排生产订单及工序。
2. 按优先级、交期、订单类型排序。
3. 对每个订单按工艺路线展开工序。
4. 对每道工序：
   a. 检查物料齐套，不齐套则延迟到最早齐套日期或标记缺料冲突；
   b. 查找可用设备/工作中心与人员；
   c. 按工作日历、班次计算可用工时窗口；
   d. 计算准备时间、加工时间、换产时间；
   e. 按正排/倒排/混合策略确定开始/结束时间；
   f. 占用设备与人员产能；
   g. 写入 ScheduleOperation。
5. 校验设备冲突、人员冲突、换产超限、交期延误。
6. 生成排程异常清单。
7. 输出甘特图数据与排程统计。
```

### 5.4 约束优先级

1. 物料齐套约束；
2. 设备/工作中心产能约束；
3. 人员技能与可用性约束；
4. 工作日历与班次约束；
5. 工序前后顺序约束；
6. 换产/准备时间约束；
7. 交期优先级约束。

### 5.5 排程结果可解释要求

每个工序排程结果必须能回答：

- 为什么排在这台设备、这个班次？
- 扣除了哪些不可用时间？
- 是否受物料齐套影响？
- 换产时间来自哪条矩阵？
- 是否存在冲突？冲突原因是什么？
- 与交期相比提前/延迟多少？

## 6. 甘特图设计

### 6.1 视图要求

- 支持按工作中心、设备、生产订单三种维度查看；
- 时间轴支持日/周/月缩放；
- 工序条显示订单号、工序、物料、数量、状态；
- 颜色区分正常、冲突、缺料、延误、已发布；
- 支持筛选：工作中心、设备、订单、状态、日期范围；
- 点击工序查看详情与来源订单；
- 支持拖拽调整开始时间或设备。

### 6.2 拖拽校验规则

拖拽后必须自动校验：

1. 设备是否可用；
2. 是否与已有工序冲突；
3. 人员是否可用且技能匹配；
4. 是否在班次/日历可用时间内；
5. 是否违反工序前后顺序；
6. 物料是否齐套；
7. 换产时间是否足够；
8. 是否导致交期延误。

校验结果：

- 通过：允许保存并更新排程；
- 不通过：提示冲突原因，允许取消或强制保存并标记异常。

### 6.3 甘特图交互要求

| 交互 | 说明 |
|---|---|
| 缩放 | 日/周/月 |
| 拖拽移动 | 调整开始时间 |
| 拖拽换设备 | 调整资源 |
| 右键菜单 | 查看详情、锁定、拆分、取消 |
| 冲突高亮 | 红色/黄色标识 |
| 依赖线 | 显示工序前后关系 |
| 导出 | 导出图片/CSV（演示级） |

## 7. 插单模拟设计

### 7.1 模拟场景

| 场景 | 输入 | 输出 |
|---|---|---|
| 新订单插入 | 物料、数量、交期、优先级 | 受影响订单、交期变化、设备冲突、缺料 |
| 设备故障 | 设备、停机开始/结束 | 受影响工序、需重排订单 |
| 物料延期 | 物料、延期到货日 | 缺料工序、交期影响 |
| 交期变更 | 订单、新交期 | 排程变化、冲突 |
| 优先级调整 | 订单、新优先级 | 排程顺序变化 |

### 7.2 What-if 对比要求

- 基准排程 vs 模拟排程并排对比；
- 展示受影响订单列表；
- 展示交期提前/延迟天数；
- 展示设备利用率变化；
- 展示新增冲突与缺料；
- 支持“采纳模拟结果”或“放弃”。

### 7.3 模拟结果字段

| 字段 | 说明 |
|---|---|
| affectedOrderCount | 受影响订单数 |
| delayedOrderCount | 延期订单数 |
| maxDelayDays | 最大延迟天数 |
| newConflicts | 新增冲突数 |
| newShortages | 新增缺料数 |
| utilizationDelta | 设备利用率变化 |
| recommendation | 建议动作 |

## 8. 排程异常清单

| 异常类型 | 说明 | 建议动作 |
|---|---|---|
| 设备冲突 | 同一设备同一时间重复占用 | 调整工序时间/设备 |
| 人员冲突 | 同一人员同一时间重复占用 | 调整人员/时间 |
| 缺料冲突 | 工序开始时物料不齐套 | 调整排程/催料/采购 |
| 交期延误 | 排程完成晚于交期 | 加班/外协/调整优先级 |
| 换产超限 | 换产时间不足或频繁切换 | 合并批次/调整顺序 |
| 班次不可用 | 工序落在非工作时段 | 调整时间/班次 |
| 技能不匹配 | 人员技能不足 | 更换人员/培训 |

要求：异常可筛选、可跳转工序、可标记处理状态、可导出。

## 10. 工程化：Service 层扩展

### 10.1 建议接口

```ts
interface SchedulingService {
  runSchedule(params: ScheduleParams): Promise<ScheduleResult>;
  getScheduleOperations(filter: ScheduleFilter): Promise<ScheduleOperation[]>;
  updateOperationTime(operationId: string, start: string, resourceId?: string): Promise<ValidationResult>;
  publishSchedule(scheduleId: string): Promise<PublishResult>;
  getScheduleExceptions(scheduleId: string): Promise<ScheduleException[]>;
}

interface CapacityService {
  getWorkCenterCapacity(workCenterId: string, from: string, to: string): Promise<CapacityBucket[]>;
  getResourceAvailability(resourceId: string, from: string, to: string): Promise<AvailabilitySlot[]>;
  checkConflict(operation: ScheduleOperation): Promise<ConflictResult>;
}

interface SimulationService {
  createScenario(input: SimulationInput): Promise<SimulationScenario>;
  runSimulation(scenarioId: string): Promise<SimulationResult>;
  compareWithBase(scenarioId: string): Promise<SimulationComparison>;
  adoptScenario(scenarioId: string): Promise<void>;
}
```

### 10.2 技术要求

- 排程引擎写成纯函数或独立模块，输入/输出可序列化；
- 排程计算可放到 Web Worker，避免阻塞 UI；
- 甘特图数据按视口懒加载；
- 页面层不直接调用 localStorage/HTTP；
- 保留 `VITE_MOCK` 开关，mock 与真实实现接口一致。

## 11. 验收标准

1. 可维护工作日历、班次、设备、人员技能、换产矩阵；
2. 可对 Phase 1 下达的生产订单运行有限产能排程；

6. 排程异常清单可分类、筛选、跳转；
7. 可模拟插单并输出受影响订单、交期变化、新增冲突；
8. 模拟结果可采纳或放弃；
9. 排程结果可发布并回写生产订单工序计划；
10. 演示数据覆盖设备冲突、缺料、换产、插单四类场景；
11. 形成 15 分钟端到端演示脚本，评审可稳定复现。

## 13. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 排程算法范围膨胀 | 延期，变成工业级 APS | 先做启发式有限产能排程，不做最优求解 |
| 约束建模过于复杂 | 开发失控 | 本阶段只做日历、班次、设备、人员技能、换产、齐套六类约束 |
| 甘特图性能问题 | 大数据量卡顿 | 视口懒加载、Web Worker、分页/聚合 |
| 拖拽校验不完整 | 排程结果不可信 | 校验规则先固化，冲突必须提示 |
| 插单模拟结果不可解释 | 评审不认可 | 输出受影响订单、交期变化、新增冲突明细 |
| 与 Phase 1 齐套口径不一致 | 排程与齐套冲突 | 复用 Phase 1 的 `inventoryService.getAvailability` |
| 演示数据不足 | 无法展示冲突场景 | 第 1 周即造设备冲突、缺料、换产、插单场景 |

## 15. 立即启动的 3 件事

1. **固化排程约束口径**：明确日历、班次、设备产能、人员技能、换产、齐套六类约束的计算规则，形成 1 页设计说明；
2. **先做启发式排程引擎**：不追求最优解，先保证“有限产能 + 工序顺序 + 物料齐套 + 换产”可运行、可解释；
3. **造冲突演示数据**：第 1 周即准备设备冲突、缺料、换产、插单四类场景，否则甘特图和模拟功能无法验收。

---

## 16. 一句话总结

> Phase 2 的核心是把 Phase 1 的“计划订单”变成“工序级可执行作业计划”：用有限产能排程引擎 + 甘特图拖拽 + 插单模拟，回答“在哪台设备、哪个班次、什么时间做、插单影响谁”；先做启发式、可解释、可演示的 APS，不追求工业级最优算法。
