# DIERP 下一阶段实施计划
## Phase 1：MRP/MPS 计划闭环 + 计划订单 + 齐套缺料

| 项目 | 内容 |
|---|---|
| 文档版本 | v0.1 |
| 适用阶段 | MVP 之后第一阶段 |
| 建议周期 | 4 周（可按团队规模压缩或拉长到 5–6 周） |
| 核心目标 | 在现有执行层 MVP 上补齐“需求 → MPS → MRP → 计划订单 → 确认下达 → 齐套/缺料”的最小计划闭环 |

## 1. 阶段目标与边界

### 1.1 本阶段要解决的问题

当前 MVP 已覆盖销售订单、BOM、工艺路线、生产订单、LOT 卡、工序报工、领料等执行层数据，但生产订单主要依赖人工判断，系统尚不能自动回答：

- 需要生产什么、生产多少？
- 什么时候需要开始生产/采购？
- 现有库存、在途、在制能否满足？
- 缺什么料、缺多少、最早什么时候能齐套？
- 哪些计划订单需要确认、下达或调整？

### 1.2 本阶段交付结果

形成 DIERP 第一个“计划驱动”的可演示版本：

1. 维护物料计划参数；
2. 汇总销售订单/预测生成轻量 MPS；
3. 运行 MRP，生成计划生产订单与计划采购订单；
4. 计划订单可确认、下达、取消，并保留来源追溯；
5. 按工单/计划订单做齐套分析，输出缺料清单与异常清单；
6. 演示数据覆盖 3 层 BOM、多交期订单和缺料场景；
7. 页面层不直接依赖 localStorage，service 层可切换 mock/真实接口。

### 1.3 本阶段不做

- APS 有限产能排程、甘特图拖拽、插单模拟；
- IQC/IPQC/FQC/OQC 完整质量闭环；
- 设备台账、点检、故障、OEE；
- 标准成本、实际成本归集、差异分析；
- 完整应收应付、总账、自动凭证；
- SRM 在线协同、WMS 条码/库位/波次；
- 替代料、多工厂、多组织、多币种等高级能力。

## 5. 可用量统一口径

所有看板、MRP、齐套分析必须使用同一公式：

```text
可用量 = 现有库存
       − 已分配/预留
       + 在途采购（按预计到货日）
       + 在制工单（按预计完工日）
       − 安全库存
```

要求：

1. 公式封装在 `inventoryService.getAvailability(materialId, asOfDate)`；
2. 页面不得自行拼接口径；
3. MRP 按需求日期滚动计算，不使用单一静态可用量；
4. 齐套分析展示缺口时，必须注明扣减了哪些库存/在途/在制。

## 6. MRP 运算逻辑

### 6.1 输入

- 销售订单/预测生成的独立需求；
- BOM 结构；
- 物料计划参数；
- 库存、在途、在制；
- 工作日历；
- MRP 运行参数。

### 6.2 计算步骤

```text
1. 收集独立需求：销售订单 + 预测 + 安全库存触发。
2. 按物料和需求日期汇总毛需求。
3. 按低层码从低到高逐层展开 BOM。
4. 对每个物料按日期滚动计算：
   净需求 = 毛需求 − 可用量 + 安全库存
5. 若净需求 > 0：
   按批量规则调整建议数量；
   按提前期倒推开始日期；
   生成计划生产订单或计划采购订单。
6. 计划生产订单作为下层物料的毛需求继续展开。
7. 输出计划订单、缺料、异常和运行日志。
```

### 6.3 结果可解释要求

每个计划订单必须能回答：

- 来源哪张销售订单/预测/MPS 行？
- 处于 BOM 第几层？
- 扣减了哪些库存、在途、在制？
- 为什么是这个数量、这个开始日期？
- 使用了什么批量规则和提前期？

## 7. MPS 设计

### 7.1 视图要求

- 按周/按日汇总；
- 可按物料、交期、优先级筛选；
- 可下钻到销售订单/预测明细；
- 支持人工调整 MPS 数量与日期；
- 调整后标记“已人工干预”，重跑 MRP 时保留。

### 7.2 MPS 状态

| 状态 | 说明 |
|---|---|
| 草稿 | 系统汇总，可调整 |
| 已确认 | 作为 MRP 独立需求输入 |
| 已关闭 | 不再参与 MRP |

## 8. 计划订单状态机

```text
建议 → 已确认 → 已下达
  ↓        ↓
已取消   已取消
```

规则：

1. 只有“建议”状态可批量确认；
2. “已确认”可下达，生产类生成正式生产订单，采购类生成采购申请记录；
3. 已下达计划订单保留来源追溯，不允许直接删除；
4. 取消需记录原因；
5. 重跑 MRP 不覆盖已确认/已下达计划订单，只生成新增建议。

## 9. 齐套分析与异常清单

### 9.1 齐套分析规则

按生产订单/计划订单检查：

- 所需物料及数量来自 BOM；
- 按需求日期扣减可用库存、在途、在制；
- 输出齐套/不齐套；
- 不齐套时输出缺料物料、缺口数量、最早可齐套日期、建议采购/生产动作；
- 支持按工单、物料、缺料日期筛选。

### 9.2 MRP 异常类型

| 异常类型 | 说明 | 建议动作 |
|---|---|---|
| 逾期订单 | 开始日期早于当前日期 | 提前采购/调整交期 |
| 物料短缺 | 可用量不足以满足需求 | 生成计划采购/生产 |
| 建议提前 | 需求日期提前 | 调整计划订单 |
| 建议推迟 | 需求日期推迟 | 调整计划订单 |
| 安全库存触发 | 低于安全库存 | 补货建议 |
| 批量不满足 | 低于 MOQ/最小批量 | 按规则调整 |

## 11. 工程化：Service 层抽象

### 11.1 目标

当前纯前端 localStorage 可继续用于演示，但页面层不得直接读写 localStorage。

### 11.2 建议接口

```ts
interface PlanningService {
  getPlanningParams(materialId?: string): Promise<MaterialPlanningParam[]>;
  savePlanningParam(param: MaterialPlanningParam): Promise<void>;
  runMrp(params: MrpRunParams): Promise<MrpRunResult>;
  getPlannedOrders(filter: PlannedOrderFilter): Promise<PlannedOrder[]>;
  confirmPlannedOrders(ids: string[]): Promise<void>;
  releasePlannedOrders(ids: string[]): Promise<ReleaseResult>;
}

interface InventoryService {
  getAvailability(materialId: string, asOfDate: string): Promise<InventoryAvailability>;
  getShortageByOrder(orderId: string): Promise<ShortageItem[]>;
}

interface OrderService {
  createProductionOrderFromPlanned(plannedOrderId: string): Promise<string>;
  createPurchaseRequestFromPlanned(plannedOrderId: string): Promise<string>;
}
```

### 11.3 切换策略

- 保留 `VITE_MOCK` 开关；
- mock 实现走内存/localStorage；
- 真实实现走 HTTP；
- MRP 运算写成纯函数，输入/输出可序列化，便于后续搬到后端或 Web Worker。

## 14. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| MRP 口径不统一 | 结果不可信，返工 | 先写 1 页口径说明，统一 service 实现 |
| 演示数据太少 | MRP 结果无说服力 | 第 1 周即扩充 3 层 BOM 与缺料场景 |
| 页面直接读写 localStorage | 后续切后端成本高 | 本阶段强制 service 层收口 |
| 计划订单与正式工单重复 | 数据混乱 | 明确状态机与来源字段，重跑不覆盖已确认 |
| 范围膨胀到 APS/成本 | 第一迭代失焦 | 本阶段明确不做 APS、成本、QMS、EAM |
| 批量规则过于复杂 | 开发延期 | 先支持逐批、固定批量、最小/最大、整数倍四类 |

## 17. 一句话总结

> 下一步先做“MPS → MRP → 计划订单 → 确认下达 → 齐套/缺料”的最小计划闭环，同时完成 service 层抽象和演示数据扩充；APS、质量、设备、成本、业财与供应链协同放到后续阶段，按“计划 → 排程 → 质量/设备 → 成本 → 业财/供应链”的节奏推进。
