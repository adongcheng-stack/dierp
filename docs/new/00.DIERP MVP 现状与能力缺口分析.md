# DIERP MVP 现状与能力缺口分析

## 1. 当前 MVP 已覆盖的范围

当前 MVP 已经覆盖了制造 ERP 的**执行层骨架**：

> 销售订单 → BOM/工艺路线 → 生产订单 → 派工/报工 → 领料

并具备基础支撑能力：

- 基础的 LOT 卡；
- 基础的工序报工记录；
- 销售订单、生产订单、物料主数据、BOM、工艺路线、工作中心等核心执行数据；
- 新建、编辑、审批、下达、完成、关闭、发货、签收、对账、领料等业务操作；
- 纯前端内存数据 + localStorage 持久化的可交互演示能力。

从演示和业务验证角度看，MVP 已经能够证明：

1. 制造执行链路的核心单据可以串起来；
2. 关键业务动作可以在系统中完成；
3. 演示数据结构与真实接口方向一致；
4. 系统具备继续向制造 ERP 深化的基础。

---

## 2. 本质判断：仍是“业务记录系统”，不是“计划与控制系统”

尽管 MVP 覆盖了执行层骨架，但它本质上仍然是一个**“业务记录系统”**，还不是一个**“计划与控制系统”**。

主要表现：

| 维度 | 当前 MVP 状态 | 计划与控制系统要求 |
|---|---|---|
| 生产来源 | 生产订单主要依赖人工建立或判断 | 由销售订单/预测/MPS/MRP 自动推导 |
| 物料需求 | 缺少净需求运算与计划订单 | 自动展开 BOM、扣减库存/在途/在制，生成计划订单 |
| 采购/生产时机 | 依赖人工经验 | 按提前期、批量规则、交期自动建议 |
| 齐套与缺料 | 缺少系统性齐套分析 | 按工单/计划订单输出缺料与最早齐套日期 |
| 产能约束 | 工作中心更多是静态主数据 | 设备、班次、人员、换产等约束进入排程 |
| 管理闭环 | 以业务操作记录为主 | 计划、执行、反馈、异常、改进形成闭环 |
| 成本与经营 | 缺少成本对象与差异分析 | 工单/产品成本可见，业务动作驱动财务结果 |

结论：

> 当前 MVP 完成了“执行层数据模型”和“业务操作闭环”的验证，但尚未建立“计划驱动”和“管理闭环”能力。

---

## 3. 对标可实际投产制造 ERP 的两条主线缺口

对标一个可实际投产的制造 ERP，当前 MVP 的缺口主要集中在两条主线：

### 3.1 主线一：从“执行记录”走向“计划驱动”

当前系统能记录“已经下了什么工单、领了什么料、报了多少工”，但不能自动回答：

- 需要生产什么、生产多少？
- 什么时候需要开始生产/采购？
- 现有库存、在途、在制能否满足？
- 缺什么料、缺多少、最早什么时候齐套？
- 设备、人员、班次、换产约束下，计划是否可执行？
- 插单、设备故障、物料延期后，哪些订单受影响？

这条主线的核心缺口包括：

1. **MRP/MPS 计划引擎**；
2. **可用量统一口径**；
3. **BOM 多层展开与净需求计算**；
4. **计划生产订单/计划采购订单**；
5. **齐套分析与缺料清单**；
6. **APS 有限产能排程**；
7. **甘特图与插单模拟**；
8. **计划异常与调整闭环**。

### 3.2 主线二：从“业务操作”走向“管理闭环”

当前系统能完成业务动作，但动作之后的管理闭环还不完整：

- 质量检验结果是否形成预防、管控、追溯、改进闭环？
- 设备故障与停机是否反哺产能与排程？
- 工单实际领料、报工、费用是否形成成本对象？
- 业务单据是否自动触发财务结果？
- 批次是否能正向/反向追溯？
- 计划达成率、交付率、库存周转、OEE、成本偏差是否可见？

这条主线的核心缺口包括：

1. **轻量 QMS**：IQC/IPQC/FQC/OQC、不合格品闭环、SPC 基础能力；
2. **轻量 EAM**：设备台账、点检、故障、停机、OEE；
3. **制造成本核算**：标准成本、实际归集、差异分析、WIP 价值；
4. **业财一体化**：业务单据驱动应收应付与自动凭证；
5. **双向追溯**：成品批次 ↔ 原材料批次 ↔ 工单/工序/设备/客户；
6. **经营看板与报表体系**：交付、计划、库存、质量、设备、成本。

---

## 4. 缺口分层总结

| 层级 | 当前 MVP | 目标制造 ERP | 关键缺口 |
|---|---|---|---|
| 执行层 | 销售订单、生产订单、派工/报工、领料、LOT 卡 | 执行数据完整、可追溯 | 批次追溯、工序质量、设备停机 |
| 计划层 | 人工建单、人工判断 | MPS/MRP 自动推导、APS 排程 | MRP/MPS、计划订单、齐套、APS |
| 质量层 | 基础记录 | 检验计划、不合格闭环、SPC | QMS |
| 设备层 | 工作中心主数据 | 设备台账、点检、故障、OEE | 轻量 EAM |
| 成本层 | 领料/报工记录 | 标准成本、实际成本、差异 | 成本核算 |
| 财务层 | 业务单据 | 业财自动凭证、应收应付 | 业财一体化 |
| 决策层 | 业务列表 | 经营看板、追溯、绩效 | 报表与追溯体系 |

---

## 5. 下一步演进判断

当前 MVP 已经完成了**执行层数据模型**的验证。接下来的核心命题不是继续堆业务记录页面，而是：

> 在现有 BOM、工艺路线、工单、报工数据之上，长出“计划引擎”和“成本引擎”。

建议演进节奏：

1. **先补计划驱动**：MRP/MPS → 计划订单 → 齐套/缺料；
2. **再补可执行排程**：APS 有限产能排程 → 甘特图 → 插单模拟；
3. **再补管理闭环**：轻量 QMS + 轻量 EAM；
4. **再补成本真相**：制造成本核算 + 差异分析；
5. **再补业财与供应链协同**：自动凭证、SRM、WMS、双向追溯、经营看板。

---

## 6. 一句话总结

> 当前 MVP 已经覆盖制造 ERP 的执行层骨架，但本质上仍是“业务记录系统”，不是“计划与控制系统”。下一步的关键，是在现有执行数据之上补齐“计划驱动”和“管理闭环”两条主线：先做 MRP/MPS 计划闭环，再做 APS 排程，随后补质量、设备、成本、业财与追溯，最终从“记录工具”走向真正的制造 ERP。
