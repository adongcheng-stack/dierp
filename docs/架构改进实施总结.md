## 二、实施内容

### 2.1 统一错误处理模块

#### 创建文件
- `backend/common/exceptions.py`

#### 功能说明
创建了统一的异常处理体系，包括：

1. **BusinessException（业务异常基类）**
   - 提供统一的错误响应格式
   - 包含错误代码（error_code）、错误详情（detail）、额外数据（extra_data）

2. **ValidationException（验证异常）**
   - 用于数据验证失败
   - 包含字段名（field）和验证失败的值（value）

3. **NotFoundException（资源不存在异常）**
   - 用于资源不存在的情况
   - 包含资源类型（resource_type）和资源ID（resource_id）

4. **ConflictException（资源冲突异常）**
   - 用于资源冲突（如重复创建）
   - HTTP状态码 409

5. **ErrorCodes（错误代码常量）**
   - 定义所有错误代码常量
   - 便于统一管理和使用

#### 使用示例

```python
from backend.common.exceptions import NotFoundException, ValidationException, ErrorCodes

# 资源不存在
raise NotFoundException(
    resource_type="Customer",
    resource_id=customer_id
)

# 验证异常
raise ValidationException(
    error_code=ErrorCodes.MATERIAL_NOT_ACTIVE,
    detail="物料状态非激活",
    field="material_status",
    value=material.status
)
```

### 2.2 验证服务模块

#### 创建文件
- `backend/common/utils/validators.py`

#### 功能说明
创建了统一的验证服务，包括：

1. **ValidationResult（验证结果类）**
   - 包含验证是否通过（is_valid）
   - 错误列表（errors）
   - 警告列表（warnings）

2. **BOMValidator（BOM验证器）**
   - `validate_bom_structure()`: 验证BOM结构完整性
   - `validate_bom_quantities()`: 验证BOM数量合理性
   - `validate_bom_hierarchy()`: 验证BOM层级关系（防止循环引用）
   - `validate_bom()`: 完整的BOM验证

3. **RoutingValidator（Routing验证器）**
   - `validate_routing_structure()`: 验证Routing结构完整性
   - `validate_routing_operations()`: 验证Routing工序顺序
   - `validate_routing_work_centers()`: 验证Routing工作中心有效性
   - `validate_routing_times()`: 验证Routing时间参数合理性
   - `validate_routing()`: 完整的Routing验证

4. **ProductionVersionValidator（生产版本验证器）**
   - `validate_production_version_status()`: 验证生产版本状态

#### 使用示例

```python
from backend.common.utils.validators import BOMValidator

# BOM验证
bom_data = {
    "parent_material_code": "MAT-001",
    "items": [...]
}

# 验证失败时会抛出ValidationException
BOMValidator.validate_bom(bom_data, db)
```

### 2.3 服务层

#### 创建文件
- `backend/services/__init__.py`
- `backend/services/mapping_service.py`
- `backend/services/sales_order_service.py`
- `backend/services/production_order_service.py`
- `backend/services/README.md`

#### 功能说明

1. **MappingService（映射服务）**
   - 负责本厂编号到物料编码和生产版本的映射逻辑
   - 主要方法：
     - `find_mapping()`: 查找本厂编号映射
     - `resolve_material_code()`: 解析本厂编号到物料编码和生产版本
     - `calculate_unit_conversion()`: 计算单位转换
     - `calculate_production_quantity()`: 计算生产数量

2. **SalesOrderService（销售订单服务）**
   - 负责销售订单的创建和业务逻辑处理
   - 主要方法：
     - `validate_customer()`: 验证客户是否存在
     - `validate_quotation()`: 验证报价单
     - `resolve_material_info()`: 解析物料信息
     - `calculate_unit_info()`: 计算单位转换信息
     - `create_sales_order()`: 创建销售订单

3. **ProductionOrderService（生产订单服务）**
   - 负责生产订单的创建和业务逻辑处理
   - 主要方法：
     - `validate_sales_order()`: 验证销售订单
     - `validate_production_version()`: 验证生产版本
     - `resolve_material_code()`: 解析物料编码
     - `calculate_production_quantity()`: 计算生产数量
     - `create_production_order()`: 创建生产订单

#### 使用示例

```python
from backend.services.sales_order_service import SalesOrderService

# 创建销售订单
order_data = {
    "customer_id": "CUST-001",
    "product_number": "HS10-04-0001",
    "quantity": 100,
    # ... 其他字段
}

db_order = SalesOrderService.create_sales_order(
    order_data=order_data,
    current_user=current_user.username,
    db=db
)
```

### 2.4 API路由重构

#### 重构文件
- `backend/api/routers/sd.py` - `create_sales_order()` 函数
- `backend/api/routers/pp.py` - `create_production_order()` 函数

#### 重构说明

**重构前：**
- 业务逻辑直接写在API路由中
- 函数长度超过150行
- 验证逻辑分散
- 错误处理不统一

**重构后：**
- 业务逻辑移到服务层
- API路由只负责接收请求和返回响应
- 统一的异常处理
- 代码更简洁、可维护

#### 重构示例

**重构前（sd.py）：**
```python
@router.post("/sales-orders")
async def create_sales_order(order: SalesOrderCreate, db: Session, current_user: User):
    # 150+ 行业务逻辑代码
    customer = db.query(Customer).filter(...)
    if not customer:
        raise HTTPException(...)
    # ... 更多验证和处理逻辑
```

**重构后（sd.py）：**
```python
@router.post("/sales-orders")
async def create_sales_order(order: SalesOrderCreate, db: Session, current_user: User):
    try:
        order_data = {...}
        db_order = SalesOrderService.create_sales_order(
            order_data=order_data,
            current_user=current_user.username,
            db=db
        )
        return db_order
    except BusinessException:
        raise
    except Exception as e:
        raise BusinessException(...)
```

### 2.5 全局异常处理器

#### 修改文件
- `backend/api/main.py`

#### 功能说明
添加了全局异常处理器，统一处理 `BusinessException` 异常，确保所有错误响应格式一致。

```python
@app.exception_handler(BusinessException)
async def business_exception_handler(request: Request, exc: BusinessException):
    """业务异常处理器"""
    return JSONResponse(
        status_code=exc.status_code,
        content=exc.detail
    )
```

## 三、实施效果

### 3.1 代码质量提升

1. **代码可读性** ✅
   - API路由函数从150+行减少到30行左右
   - 业务逻辑集中在服务层，职责清晰

2. **代码可维护性** ✅
   - 服务层方法可复用
   - 修改业务逻辑只需修改服务层，不影响API路由

3. **错误处理统一** ✅
   - 所有错误使用统一的异常类
   - 错误响应格式一致，便于前端处理

### 3.2 架构改进

1. **分层清晰** ✅
   - API路由层：接收请求、返回响应
   - 服务层：业务逻辑处理
   - 数据模型层：数据访问

2. **职责分离** ✅
   - 验证逻辑集中在验证服务
   - 业务逻辑集中在服务层
   - API路由只负责HTTP交互

### 3.3 可测试性提升

1. **服务层可独立测试** ✅
   - 服务方法使用静态方法，便于单元测试
   - 不依赖HTTP请求，可以单独测试业务逻辑

2. **验证逻辑可独立测试** ✅
   - 验证器可以单独测试
   - 不依赖数据库，可以使用mock数据
